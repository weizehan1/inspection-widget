## 资源纪律核对（阶段 8 Step 3）

全仓 grep `new Bitmap`、`Graphics.FromImage`、`GetHdc`、`CreateCompatibleDC`、`SetWindowsHookEx`、`new Timer`、`FileStream`，逐处核对结论：

| 资源 | 点位 | 释放/成对结论 |
| --- | --- | --- |
| Bitmap（PrintWindow 路径） | `src/Capture/WindowCapture.cs` TryPrintWindow | Graphics 用 using；失败 Dispose；裁剪成功 Dispose 原图改用裁剪图；移动/黑图复核 Dispose 结果图；成功时所有权移交调用方。超时迟到图登记回收表、由迟到线程自行 Dispose，不提前释放 |
| Bitmap（BitBlt 路径） | `src/Capture/WindowCapture.cs` CaptureViaBitBlt | Graphics 用 using（CopyFromScreen）；异常 catch Dispose；移动/黑图复核 Dispose；成功移交调用方 |
| Bitmap（面板待保存图） | `src/MainForm.cs` `_pendingImage` | 所有权在面板：新截图开始、保存成功、窗体 Dispose 三处释放，登记有代次守卫防迟到重登记；Saver 从不释放传入图 |
| Graphics.FromImage | WindowCapture 两处 | 均在 using 内 |
| GetHdc | WindowCapture PrintWindow 线程内 1 处 | 与 `ReleaseHdc` 在 finally 中成对 |
| CreateCompatibleDC / CreateCompatibleBitmap 等裸 GDI 句柄 | 全仓无使用 | BitBlt 路径走 `Graphics.CopyFromScreen`，无手工 DC/位图句柄需配对 |
| SetWindowsHookEx（鼠标/键盘） | `src/Capture/HookManager.cs` | 与 `UnhookWindowsHookEx` 成对：挂钩失败路径先卸已挂钩、钩子线程消息循环退出时卸钩、FinalizeTeardown 兜底卸钩；Stop/Dispose 幂等，MainForm 状态集中点与关闭路径均调用 |
| Timer（钩子超时/延迟卸载） | HookManager `TimeoutTimer`/`DeferredTeardownTimer` | Stop 与 FinalizeTeardown 中 Dispose |
| Timer（剪贴板自动清空） | `src/Credentials/ClipboardGuard.cs` | 重启前先 Dispose 旧 Timer；Dispose 时停表 |
| Timer（反馈行，WinForms） | MainForm `_feedbackTimer` | 本次补修：此前窗体 Dispose 未释放该 Timer（靠 GC 终结），已在 `MainForm.Dispose(bool)` 中补 `Dispose()` 并随本次提交修复 |
| FileStream | `src/Config/ConfigStore.cs`（锁文件、临时文件、探针）、`src/Storage/ScreenshotSaver.cs`（占名/写入） | ConfigStore 锁流与临时流均 using；ScreenshotSaver 占名流 using、写入流成功 Dispose/失败经 CloseQuietly 关闭，两处异常路径均覆盖 |
| Font / Pen | MainForm、SettingsForm、绘制处 | Pen 均 using；缓存 Font 在各窗体 Dispose 中释放，控件只引用不重复释放 |

结论：除上表 MainForm `_feedbackTimer` 一处已修复外，未发现确定性泄漏。附带观察（记录备查、本次未改）：`HookManager.HookSession.Ready`（ManualResetEvent）未显式 Dispose——其 SafeHandle 由 GC 终结回收、每会话一个、量级可控；若在 Start 超时路径后补 Dispose，迟到挂钩线程的 `Ready.Set()` 有对已释放对象抛错的新风险，权衡后维持现状，待实机阶段如需再议。
