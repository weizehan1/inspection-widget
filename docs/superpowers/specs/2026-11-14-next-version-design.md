## 3. 产品方案

### UI. 前端整体重做（Kimi 主责，先设计再实现）

产品场景是 Windows 桌面常驻巡检小组件：重点是快速打开系统、逐项截图、辨认进度和找到文件。设计围绕这些任务展开，保持紧凑、少遮挡工作窗口；设置窗口承担复杂维护。

设计范围：
- 主面板：重新组织标题/日期、快捷链接、截图清单/计划进度、凭据和底部文件夹入口，主次清楚，常用动作直接可见。
- 设置：重做导航、编辑区、说明与应用/保存/取消的层级，覆盖设备、凭据、链接、存储、配置备份；保留原有业务能力，不要求固定沿用五页结构。
- 状态：计划开启/关闭、等待选窗、截图中、保存中、成功、失败/重试、全部点过、空名单、未配置路径、配置写保护，视觉与文字相互配合。
- 视觉规范：字体及层级、行高、间距、颜色、图标、按钮和输入控件，以及鼠标悬停、键盘焦点、禁用和选中状态，形成一套一致的规则。

Kimi 设计阶段交付：
1. 现有操作与布局问题清单，依据当前源码及可取得的真实界面，区分实测和待 Windows 核验项。
2. 两个有实际结构差异的主面板方案，以及配套设置页预览；不是只改配色。给出推荐理由、常用内容下的尺寸、长名单和高 DPI 下的表现。
3. 可预览的设计稿或交互原型，覆盖正常、截图中、失败和计划完成状态。HTML 原型可作为沟通载体，不代表把桌面程序改成网页。
4. 设计方案选定后，交付 `DESIGN.md`（视觉规范与组件规则）和控件/业务状态对照，供 PI 执行者接线，并作为视觉验收依据。

设计约束与建议：
- 沿用 WinForms / .NET Framework 4.8，不因重做界面引入 Electron/WebView 或第三方 UI 运行依赖。
- 不把现有 230 逻辑像素宽度当作硬限制；由内容和实际桌面场景决定宽度，仍保留工作区限制、滚动、托盘和截图时隐藏行为。
- 不把设备点击、对勾、快捷链接、复制凭据设计成难以区分的同一种操作；“已点过”与“保存成功”不得仅靠颜色区分。
- 所有新功能放进整体结构中统一设计，不在旧面板上继续堆放按钮。
- 顶部日期独立一行是当前可用建议，最终排布由选定设计决定；完整显示、无重叠是验收要求。

### A. 快捷链接

设置中增加“快捷链接”管理项：名称、URL、启用状态、排序，支持新增、编辑、删除。
可配置“内网堡垒机一期”“内网堡垒机二期”，真实地址由用户在设置中填写，不写死在程序、文档或示例配置里。
主界面单独显示已启用的链接按钮；点击后通过系统默认浏览器打开，不纳入截图计划的对勾统计。
接受完整 `http://`、`https://` 地址，包括内网 IP、端口和路径；只做格式校验，不以公网可达性作为保存条件。拒绝其他协议，启动失败显示明确提示。
新字段必须贯通配置加载、克隆、草稿、应用/取消、普通导入导出与备份；旧配置缺少链接字段时按空列表处理。

### B. 巡检计划模式

增加明确的“计划模式”开关。建议升级后默认关闭，开启后以当前截图设备列表作为本轮清单，无需维护第二份设备名单。
设备行展示独立对勾和“已点过 X / Y”；仍允许再次点击设备进行截图，重复点击不取消完成标记、不重复累计。

本稿按用户原话设计：一次设备点击被当前截图状态机接受后，即标记“已点过”；忙碌时被拒绝的点击不计数。对勾只表示操作记录，不宣称截图已保存。
Esc/右键取消、超时、抓图失败或落盘失败均保留“已点过”标记，另以现有反馈提示截图问题。这是需要用户重点确认的语义；如希望对勾表示截图已保存，须在实施前改为保存成功时标记。
提供单项“恢复未点”和“重置本轮”入口；重置本轮需确认，普通重复截图不影响标记。

建议补充的运行规则（尚待用户审阅）：
- 当天进度重启后恢复；按系统本地日期开始新一天，自动清空新一天的勾选。
- 关闭计划模式只隐藏进度，同日重新开启恢复；重置本轮才清空。
- 同日新增设备为未点，删除设备移出统计，排序不影响勾选；通过设置改名保留对应状态，导入替换设备则开始新一轮，避免错误继承。
- 当日进度存独立本地状态文件，不混入可分享配置或配置导出。进度保存失败要提示，不静默声称重启可恢复。
- 跨午夜时，旧请求和重试按既有 CaptureRequest 的日期保存；不得把旧回调写入新一天的进度。实现时为计划轮次附带日期/代次，补充跨日测试。

### C. 全部勾选后的询问

当前计划非空、首次由未全勾变为全勾后，安排一次询问：“所有项目已点过，是否打开巡检文件夹？”按钮为“打开文件夹”“稍后”。
最后一项点击会先进入截图流程，询问必须等本次选窗/截图/保存结束后再弹出，不能抢走选窗焦点；若有保存失败或尚无截图，弹窗中如实说明，不能称为“截图全部完成”。
一轮只询问一次；“稍后”、界面刷新、重启、重复截图和取消单项再勾回均不反复弹。新一天或明确重置本轮才允许再次询问。
空清单不弹；删除/导入设备等配置操作不直接触发完成弹窗。
“打开”进入本轮的实际截图目录：正常保存优先今日巡检目录；全部暂存时进入实际暂存目录；多处保存时说明存在暂存截图并提供对应目录入口。没有可打开目录时显示“本轮尚无已保存截图”，不凭空创建文件夹。

### D. 底部路径入口

底部改为明确的“打开巡检文件夹 ↗”按钮或 LinkLabel，路径另行展示，悬停可看完整路径。
路径过长可以省略，但动作名称不能被路径挤掉；键盘 Tab/Enter 可操作，辅助名称明确。
沿用已有打开目录与定位截图逻辑，与完成询问共享同一目录解析入口，避免两处打开不同目录。
配置读取失败时保留重试入口，不能因替换路径控件而丢掉写保护恢复功能；未设置目录、目录不存在、启动失败分别提示。

### E. 日期与文字布局（纳入整体重做）

建议第一行保留标题、设置/最小化/关闭，第二行完整显示日期；计划进度使用自己的行，不继续挤标题栏。
按文字实测尺寸和控件 PreferredSize 布局，留出上下空间，统一核对 DPI 与应用缩放的组合，不只固定加宽日期控件。
设备名、链接名、反馈、路径与新增按钮一起检查；允许长路径/长名称省略并提供完整提示，日期和必要操作文案必须完整显示。
保留右下角锚定、滚动、折叠和托盘行为。

## 5. 验收场景

1. 配置一期/二期名称和不同内网 HTTP(S) 地址，保存并重开后可点开默认浏览器；无效地址有明确提示。
2. 开启计划模式，A 点两次只计一次；取消截图后保留“已点过”，失败信息仍清晰；模式关闭/重开及程序重启符合上述约定。
3. 最后一项点选时不抢焦点；截图链路结束后只询问一次；选择“稍后”后刷新/重启不再弹。
4. 正常落盘、全部暂存、部分暂存、无截图、目录丢失及网络目录不可用时，目录入口与文案准确。
5. 跨日、新增/删除/改名/排序/导入替换、重置与空名单，不产生错误计数或重复完成弹窗。
6. 真实 Windows 上至少覆盖系统 DPI 100%/125%/150%/200% 下应用缩放 100%，以及系统 DPI 100% 下应用缩放 125%/150%/200%；混合 DPI 切屏至少一组。检查日期无截断、控件无相交、底部入口可见。
7. 旧配置、配置导入导出、应用/取消、写保护恢复、凭据清理、截图重试/不覆盖、托盘与折叠通过相称的回归。
8. 主面板和设置界面与选定设计一致，层级、字体、间距、图标与交互状态统一；原五项功能自然融入整体结构，常用操作无需猜测入口，长名单和小工作区仍可使用。
