# 巡检截图小组件白皮书

> 版本：v0.3 终审定稿版 · 日期：2026-11-02（2026-11-02 修订：凭据与集群均按实际配置数量渲染，不再固定槽位）
> 状态：终审定稿。设计全部锁定，可直接作为开发与验收基准。本稿为设计文档，尚无源码与可运行成品；以下技术方案仍须 Windows 实机验证。已并入远端审计修订（commit 3a1b47d）的工程收紧项。

## 1. 这是个什么东西

一个常驻在 Windows 桌面右下角的小组件，专门解决巡检时反复截图、反复建文件夹、反复改文件名的问题，外加巡检中反复输入账号密码的问题。

它做两件事：

- **截图归档：** 你点一个集群名，再点一个窗口，截图就自动存进当天的日期文件夹，文件名就是集群名。
- **一键复制凭据：** 面板上按实际配置数量显示凭据按钮（最多 10 个），在设置里提前填好账号或密码类内容，点一下就复制到剪贴板，切到目标窗口直接粘贴。用几个就显示几个，不留空槽。

没有账号体系、没有主动联网、没有安装步骤，目标 Windows 机器具备第 5 节要求的运行时且允许运行时，拷贝 exe 后即可使用。

本稿的目的不是介绍功能清单，而是把实现方式、边界和坑提前研究清楚，避免做出来才发现截不到、存不对、换台机器就用不了。

## 2. 已确认的需求

以下事项已在沟通中逐项确认，作为设计的硬约束，不再变动：

- **运行环境：** Windows 系统，不需要安装任何依赖或运行时。
- **截图对象：** 只截选中的那个窗口，不做全屏截图。
- **目录结构：** 只按日期分文件夹，即 `根目录\日期\`，不再按集群名建子文件夹；集群名体现在文件名上，规则见第 7 节。
- **集群自定义：** 集群名由使用者自己增删，第一次设置后保存下来，下次打开程序还在。面板按实际集群数量渲染，有几个显示几个；数量级通常为 6 到 10 个。
- **保存根目录：** 只在首次打开时弹窗让使用者选一次，选完持久化保存到程序配置中；后续每次启动直接默认使用该位置，不再重复询问。之后如需更换，在设置里随时可改。
- **管理员启动：** 程序默认以管理员身份启动，每次打开多一步系统确认弹窗，换取截得到管理员窗口的能力。
- **窗口形态：** 右下角置顶小窗，带最小化按钮；最小化后缩到任务栏，点任务栏图标即可重新打开组件。不进托盘。
- **开机自启：** 不做。需要时手动打开程序。
- **剪贴板按钮：** 最多 10 个，按实际配置数量显示，在设置里像集群一样增删条目、预置名称和内容，点一下复制到剪贴板。内容按密码对待，加密保存，细则见第 8 节。
- **分享方式：** 只分享 `.exe` 本体，不做配置或模板导出功能，细则见第 9 节。

## 3. 核心交互流程

### 3.1 截图流程，两步完成一张

1. 在右下角小面板上点击一个集群名，例如“集群 A”，该按钮进入选中高亮状态，组件进入待截图状态。
2. 移动鼠标到目标程序窗口上并单击，组件识别鼠标所在窗口，截取该窗口画面。
3. 截图按第 7 节规则自动保存到当天日期文件夹，面板上短暂显示保存成功提示和文件名，组件回到待命状态，等待下一次操作。

整个过程不弹出保存对话框，不需要手动选路径，也不需要手动改名。一个集群在一次巡检中通常只截一张图，所以文件名直接用集群名即可辨认归属。

### 3.2 复制凭据流程，一步完成

1. 在面板的凭据区点击一个预置按钮，例如“平台账号”。
2. 程序把该按钮预置的内容解密后写入剪贴板，面板短暂提示“已复制”。
3. 切到目标窗口粘贴即可。

复制后的剪贴板清空策略见 8.3：设置里提供“复制后 30 秒自动清空剪贴板”开关，粘完忘在剪贴板里的风险靠它兜底。

### 3.3 必须补上的交互细节

- **取消操作：** 进入待截图状态后，按 Esc、点击鼠标右键，或再次点击已选中的集群名，均应立即取消本次待截图状态，恢复待命，避免误点。
- **切换目标集群：** 在待截图状态下直接点击另一个集群名，直接将选中目标切换为新集群，保持待截图状态。
- **点到无效区域怎么办：** 如果第二下点在了小组件自己身上（非集群按钮区）、桌面空白处或系统任务栏上，应忽略本次点击、给出轻提示并保持待截图状态，不能把组件本身或桌面截进去，也不能算作完成。
- **截图反馈：** 每次保存后至少给出文件名和所在文件夹，并提供一个“打开今日文件夹”入口。巡检时需要立刻确认图截对了没有，不能保存完毫无动静。

### 3.4 焦点与点击拦截规则

第二下点击既要用来选窗口，又不能把目标窗口的业务操作误触发，规则固定如下：

- **按需挂载：** 低级鼠标钩子（`WH_MOUSE_LL`）只在组件处于待截图状态时挂载，平时绝不挂载；退出待截图状态后立即卸载。
- **默认不放行、成对拦截：** 在目标窗口上点击左键时，必须成对吃掉这次点击的按下（`WM_LBUTTONDOWN`）与随后的抬起（`WM_LBUTTONUP`）事件，都不向目标窗口传递。只拦按下、不拦抬起会让目标窗口收到孤立的 `MouseUp`，仍可能触发网页按钮或菜单；成对拦截后，即使点在“关闭”“提交”一类按钮上，也不会把按钮真的点下去。
- **点在组件自身时放行：** 点击坐标落在小组件自身范围内时放行该次点击，让组件自己的按钮（如切换集群、取消、设置）正常响应。
- **异步解耦：** 钩子回调内只记录点击坐标并拦截消息，随后通过 `BeginInvoke` 异步切回 UI 线程执行窗口反查、截图与写盘；回调内严禁直接执行截图、写盘等耗时操作。钩子回调耗时过长（超过约 200ms）会触发 Windows 的 `LowLevelHooksTimeout` 机制，系统会强制失效钩子并把点击放行给底层窗口。

## 4. 界面应该长什么样

界面是一个贴在屏幕右下角的置顶小面板，原则是小、稳、不挡事。

- **位置：** 默认停靠在主显示器工作区（`WorkingArea`）右下角、任务栏上方，始终置顶，保证巡检时随手可点；记住上次拖动后的位置，下次打开还在原处（若原坐标超出当前屏幕，自动归位到主屏右下角）。
- **尺寸与伸缩：** 宽度约 220–280 像素（随系统 DPI 自适应）。集群按一列竖排、按实际数量渲染，6 到 10 个集群时高度仍可控，不需要滚动，也不需要改成两列或下拉选择；集群更少时面板随之更矮。凭据区同样按实际配置数量渲染，窗口高度随集群与凭据的实际数量走。小屏高度兜底只靠凭据区折叠（见下条），不采用凭据改 3 列、面板内滚动等其他兜底方式。凭据区展开/折叠、以及增删集群或凭据引起窗口高度变化时，必须以窗口底边（`Bottom`）为锚点向上伸缩——保持底边位置不变、反算新的顶部位置，并按 `Screen.WorkingArea` 做边界钳制，确保顶部不超出工作区上沿。WinForms 默认以左上角为锚点改变高度会让窗口向下伸长，下半截直接捅进任务栏下面被挡住，故严禁默认锚点伸缩。
- **内容从上到下：**
  - 顶部一行：程序名 + 当天日期，以及设置、最小化按钮。保存根目录不在顶部行展示。
  - 中部：集群按钮列表，一行一个，点击即选中。当前选中的集群用不同底色区分。
  - 凭据区：与集群列表用分区标题行分隔，不用细分隔线，按实际配置数量渲染凭据按钮，一行一个单列竖排，只显示按钮名，不显示内容。不设固定槽位，不显示置灰的空槽：使用者只配置了 5 个凭据，面板就只有 5 行凭据，窗口高度随实际数量走。已配置但解密失败的条目显示「需重设」，可点击，点击后提示去设置中重新填写。凭据条目数为 0 时，凭据区只显示分区标题与一行「未设置凭据，去设置添加」的提示行，不渲染任何按钮。凭据区可折叠：点击分区标题即可收起或展开凭据按钮，不用时收起；折叠状态持久化保存，下次打开保持上次的收起或展开状态。当集群较多、面板在小屏上过高时，收起凭据区即可压低面板高度。
  - 底部状态区：共两行——反馈一行 + 根目录常驻一行。反馈行显示保存、复制等操作结果；根目录行常驻展示保存根目录，该行即「打开今日文件夹」入口，点击打开当天日期文件夹。
- **最小化行为：** 点最小化按钮后，组件缩到任务栏，只留任务栏图标；在任务栏点击该图标即可重新打开组件。不进托盘，不做托盘图标和托盘菜单。
- **状态提示：** 状态区口径统一为「反馈一行 + 根目录常驻一行」：反馈行承载待截图、保存与复制等提示——待截图时，面板边框或标题变为醒目颜色，并显示文字“请点击要截图的窗口”；保存成功后 2 秒内在反馈行显示对勾和文件名，随后自动消失；复制凭据后在反馈行短暂显示“已复制”。根目录行常驻展示保存根目录，不随反馈消失，该行即「打开今日文件夹」入口，点击打开当天日期文件夹。

不做花哨皮肤，不做动画，不做多页签。巡检是重复劳动，按钮大、字清楚、状态一眼能看懂，比好看更重要。

## 5. 技术路线：为什么选 C# WinForms

“零依赖”的关键不是打包时把依赖藏起来，而是目标机器上本来就有的东西就能跑。下表按这个标准对比常见路线：

| 路线 | 目标机要装什么 | 程序体积 | 窗口截图能力 | 结论 |
| --- | --- | ---: | --- | --- |
| C# WinForms（.NET Framework） | 目标机已有 4.8+ 时不用装 | 约 100–300 KB | 强，直接调 Win32 | **推荐** |
| C# WPF（.NET Framework） | 目标机已有 4.8+ 时不用装 | 略大 | 强 | 可用，界面成本更高 |
| C#（.NET 8 自包含发布） | 不用装，运行时打进程序 | 约 70 MB 起 | 强 | 违背“小组件”定位 |
| AutoHotkey 脚本打包 | 严格说带解释器 | 约 1 MB | 中，需调系统接口 | 能做，长期维护弱 |
| Python + PyInstaller | 不用装，打包进程序 | 约 15–30 MB | 中 | 体积大、启动慢、易被误报 |
| Electron | 不用装，打包进程序 | 100 MB 以上 | 中 | 明显过重，排除 |
| PowerShell 脚本 | 系统自带 | 很小 | 弱 | 交互界面难做，排除 |

### 5.1 推荐方案的具体形态

- 语言与框架：C# + WinForms，目标框架固定为 .NET Framework 4.8。Windows 11 和 Windows 10 1903 起的系统内置 4.8 或更高版本；更早的 Windows 10、Server 和精简系统须先核对运行时，不能笼统承诺所有 Windows 都免安装。
- 交付物：单个 .exe 文件，不捆绑其他运行文件。运行后会生成配置，异常时还可能生成配置备份、错误日志和截图暂存文件，位置在设置中展示。
- 启动权限：程序清单（manifest）声明要求管理员权限，双击后先弹系统确认，确认后以管理员身份运行。
- 编译方式：使用 Visual Studio 2022 / MSBuild 与 .NET Framework 4.8 目标包生成 Release 版本，严禁引入任何第三方 NuGet 包（如 Newtonsoft.Json）。配置序列化统一使用系统自带的 `DataContractJsonSerializer`（`System.Runtime.Serialization`），DPAPI 加密统一使用系统自带的 `ProtectedData`（`System.Security`），截图、识别窗口、剪贴板全部使用系统自带接口与 Win32 P/Invoke。
- 单实例运行：程序以互斥锁（`Mutex`）防多开，重复双击不启动第二个实例。
- 兼容范围：以 Windows 10、Windows 11 为正式支持范围；Windows 7 理论上在装有 .NET Framework 4.8 时也能跑，但不作为承诺范围。

### 5.2 “零依赖”的准确含义

需要把话说清：这里的零依赖是指使用者不用再装 Python、.NET 运行时、运行库或任何插件，双击即可运行。它依赖的是 Windows 系统本身自带的 .NET Framework 和系统加密接口，这是系统的一部分，不是额外安装项。如果某台机器把 .NET Framework 功能关掉了，程序会无法启动，届时系统会给出明确提示，这属于极少数被精简过的系统环境。目标机缺少 4.8+、系统组件损坏或被精简时不承诺启动；开发机需要开发工具与目标包，不属于使用者的运行依赖。

## 6. 窗口截图到底怎么实现

这是整个工具技术上最容易翻车的部分。看上去是“截个图”，实际上要分三步，每一步都有坑。

### 6.1 第一步：点到的是哪个窗口

当使用者在待截图状态下点击屏幕时，程序通过系统接口按鼠标坐标反查窗口：

1. 低级鼠标钩子（`WH_MOUSE_LL`）只在待截图状态挂载（另可同时挂 `WH_KEYBOARD_LL` 监听 Esc 取消），拿到点击时的物理屏幕坐标后成对吃掉 `WM_LBUTTONDOWN` 与 `WM_LBUTTONUP` 并立即卸载钩子，规则见 3.4。钩子回调只记录坐标并拦截，随后 `BeginInvoke` 异步切回 UI 线程执行以下反查、截图与写盘，回调内不做耗时操作。
2. 用 `WindowFromPoint` 拿到坐标下最内层的子窗口句柄，再用 `GetAncestor(hwnd, GA_ROOT)` 向上追溯到它的顶层窗口。巡检软件里点到的往往是表格、文本框这类子控件，要截的是它们所属的整个程序窗口，不是那个小控件。
3. 排除无效目标：追溯结果为组件自身，或窗口类名为桌面（`Progman` / `WorkerW`）、任务栏（`Shell_TrayWnd` / `Shell_SecondaryTrayWnd`）时，本次不截图，给出轻提示并保持待截图状态。用 `IsIconic` 检查目标是否已最小化，已最小化则提示先还原窗口，不生成空图。

窗口标题同时取出来，只用于保存提示，让使用者一眼确认选对了窗口；文件名不再使用窗口标题，见第 7 节。

### 6.2 第二步：窗口画面怎么抓

有两种抓法，效果差别很大，需要组合使用：

| 抓法 | 原理 | 优点 | 缺点 |
| --- | --- | --- | --- |
| 窗口打印（PrintWindow） | 传入 `PW_RENDERFULLCONTENT (0x00000002)` 让窗口把自己重绘到内存图上 | 被遮住也能截完整窗口 | 极少数老旧硬件加速或独占渲染窗口可能截出黑图或旧画面 |
| 屏幕拷贝（BitBlt） | 按窗口实际可视矩形从屏幕上拷像素 | 所见即所得，几乎不会黑屏 | 窗口被遮住的部分会截到遮挡物，需先置前 |

组合执行策略：

1. **默认首选 PrintWindow，且必须带 `PW_RENDERFULLCONTENT (0x00000002)` 标志。** Windows 10/11 下不带此标志时，浏览器、WPF、硬件加速窗口大概率截出黑图。先按 `GetWindowRect` 的完整矩形（含透明阴影）抓图，再按 `DwmGetWindowAttribute` 的 `DWMWA_EXTENDED_FRAME_BOUNDS` 相对完整矩形的偏移量在内存中裁掉四周透明阴影边，得到实际可视画面。两种矩形严禁混用：混用会导致四周带黑边或右下角被截断。

PrintWindow 为同步阻塞调用，必须离开 UI 和钩子线程执行；超时只使本次请求失效，不代表原调用已停止，未返回前禁止再启动 PrintWindow，位图与 DC 仍由该调用独占至返回后释放。

2. **黑图/空白自动检测：** 对裁剪后的图像做像素采样检测——均匀网格采样约 225 个像素点（例如 15×15），若超过 98% 的采样点为纯黑 `RGB(0,0,0)` 或完全透明，判定抓取失败。黑图或同色采样只表示可疑，无法证明系统保护、识别旧画面或判断内容完整；采样只表示可疑，不能证明受系统保护、画面为旧画面或内容完整。合法纯色窗口须提供预览确认后保存的入口。
3. **自动回退 BitBlt：** `PrintWindow` 返回失败或被判定黑图时，自动回退屏幕拷贝——先将目标窗口置前（`SetForegroundWindow`）。回退前暂时隐藏组件并尝试将目标置前，必须检查置前结果与可见范围；仍被遮挡或窗口部分在屏外时提示用户调整，不把混入其他窗口的屏幕拷贝当成功。直接按 DWM 可视边界抓屏，不再按完整矩形抓。若目标窗口矩形与小组件自身位置重叠，因组件置顶（`TopMost`）会被截进去，须先将组件临时隐藏/透明，等待约 60ms 让 DWM 刷新一帧后再抓，抓完立即恢复组件显示。
4. **设置项兜底：** 设置里提供「截图模式」选项——`自动（推荐）` / `仅屏幕拷贝（置前抓屏）`，供个别顽固软件手动切换。

### 6.3 第三步：图片怎么存

抓到的画面先在内存里成图，再存为 PNG 文件，并及时释放 GDI 句柄与位图内存，杜绝连续截图内存泄漏。PNG 是无损格式，巡检截图里大量文字和表格线条不会糊，也不需要调压缩参数。默认不提供 JPG，文字类截图用 JPG 会出现噪点，反而不利于事后核对。单张窗口图一般在几百 KB 到 2 MB 之间，属于可接受范围。存图路径和文件名按第 7 节规则生成。

### 6.4 必须处理的坑

- **被遮挡：** 见 6.2 的组合策略（`PrintWindow` 带 `PW_RENDERFULLCONTENT` + 黑图检测 + `BitBlt` 自动回退），不要只写一种抓法就交付。
- **已最小化：** 最小化的窗口没有可抓的画面。用 `IsIconic` 检查，点到任务栏图标这类情况应提示“该窗口已最小化，请先还原窗口”，不生成空图。
- **显示缩放（高 DPI）：** 很多机器缩放设为 125% 或 150%。程序清单必须声明 Per-Monitor V2 DPI Awareness，确保坐标与位图尺寸均基于真实物理像素，否则截出来的图会发虚、尺寸对不上、只截到左上角四分之一。
- **多显示器与负坐标：** 窗口可能在副屏上，副屏在主屏左侧或上方时坐标为负数。取窗口矩形和屏幕范围时必须用虚拟屏幕真实坐标（支持负值），不能假设坐标从 0 开始，否则副屏窗口会截偏或截空。
- **窗口透明阴影边与坐标系冲突：** `GetWindowRect` 包含一圈约 7 像素的透明阴影，`DWMWA_EXTENDED_FRAME_BOUNDS` 才是实际可视边界。`PrintWindow` 先按完整矩形抓图、再按 DWM 偏移量在内存裁边；`BitBlt` 直接按 DWM 可视边界抓屏。截图最终尺寸以 DWM 可视边界为准，把阴影裁掉、把标题栏和边框完整留下。
- **组件自身入镜：** 回退 `BitBlt` 时若目标窗口与置顶的小组件重叠，组件先临时隐藏/透明并等待约 60ms（DWM 刷新一帧）后再抓，见 6.2。
- **管理员窗口（UIPI 隔离）：** 已定案默认以管理员身份启动组件，见 2 节和 5.1。这可改善普通提升权限窗口的访问，但不保证截取安全桌面、SYSTEM 进程或受保护内容；UAC 提示受系统策略影响，不能用管理员启动承诺绕过所有隔离。代价是每次打开多一步系统确认弹窗，属于已接受的取舍。

## 7. 目录与文件命名规则

### 7.1 目录结构

只按日期分一层文件夹，不再按集群名分文件夹：

```text
<保存根目录>\
├─ 2026-11-02\
│  ├─ 集群A.png
│  ├─ 集群A-1.png
│  └─ 集群B.png
└─ 2026-11-03\
   └─ 集群A.png
```

- 日期格式固定为 `yyyy-MM-dd`，例如 `2026-11-02`，由程序读取系统日期自动生成，跨天后自动切换到新日期文件夹。
- 日期文件夹按需创建：当天第一次截图时才建，没截过图不产生空文件夹。

### 7.2 文件命名

文件名直接用集群名：

- 第一张：`集群名.png`，例如 `集群A.png`。
- 同一天、同一集群再截：顺延为 `集群名-1.png`、`集群名-2.png`，序号从 1 起递增，取当前未被占用的最小序号。
- 绝不覆盖已有文件。使用 FileMode.CreateNew 原子创建候选文件，仅遇到重名冲突时顺延；禁止采用先查存在再覆盖写入。编码完成并成功关闭文件后才报告成功，失败时只清理本次创建的不完整文件，原有文件不动。
- 跨天不继承序号：新一天的日期文件夹里，第一张仍是 `集群名.png`。

这样命名的依据是一个集群在一次巡检中通常只截一张图，文件名本身就能说明归属，打开日期文件夹一眼就能核对哪个集群截了、哪个还没截。重名顺延只是兜底，不改变图的主要命名。

- 集群名保存时拦截非法字符（\ / : * ? " < > |）、控制字符、空名、. / ..、尾部空格或点、设备保留名（如 CON、NUL、COM1、LPT1，含带扩展名形式）；名称按 Windows 大小写不敏感规则查重。加载手改配置也走同一校验；最终路径须位于日期目录内，并校验追加序号后的完整路径长度。在保存设置时直接拦下并提示改名，不要等截图时才报错。

### 7.3 根目录规则

- **只问一次：** 程序仅在第一次打开、还没有保存过根目录时，弹出文件夹选择框，由使用者选定保存位置；这是唯一一次主动询问。选完立即持久化保存到程序配置中，后续每次启动直接默认使用该位置，不再弹窗询问、不再重复确认。
- 如果首次选择时取消（即从未成功选定过），程序给出明确提示，主面板禁用截图并引导去设置中选择根目录，下次启动时继续提示选择，这不算重复询问，而是首次选择尚未完成；没有设置根目录前不允许进入待截图状态，避免图存到不知道的地方。一旦选定成功，后续启动一律默认沿用，不再出现选择框。
- 设置里随时可改，改完立即生效，新截图进新根目录，旧图不搬动。
- **磁盘异常兜底：** 如果截图瞬间根目录所在磁盘（如移动硬盘、映射网络盘）断开或无写入权限，程序不能丢图。优先暂存到程序目录下的 `FallbackScreenshots\yyyy-MM-dd\`，同目录也不可写则尝试 `%LocalAppData%\InspectionWidget\FallbackScreenshots\yyyy-MM-dd\`；沿用不覆盖规则并显示实际路径。两处均失败时保留当前内存图供重试，提示“尚未保存”，不能回到待命后丢掉图或显示保存成功。

## 8. 配置与持久化

### 8.1 配置存什么

配置文件存以下信息：

- 集群名单：名称列表及显示顺序，按实际增删保存，数量级通常为 6 到 10 个。
- 保存根目录路径。
- 界面状态：面板位置、凭据区是否折叠（`IsCredentialCollapsed`）等使用习惯。
- 凭据条目列表（0–10 条）：每条含一个显示名（`Title`），加一段 DPAPI 加密后的 Base64 密文（`EncryptedSecret`）。条目数随使用者实际增删变化，不预置空条目。
- 偏好设置：截图模式偏好（自动 / 仅屏幕拷贝）、“复制后 30 秒自动清空剪贴板”开关（默认开启）。

其中只有凭据按钮的内容属于敏感信息，单独加密处理，见 8.3；其余都是普通设置。

### 8.2 配置存哪里、用什么格式

- **路径基准（严禁相对路径）：** 主路径为与 `.exe` 相同物理目录下的 `config.json`，代码中必须使用 `AppDomain.CurrentDomain.BaseDirectory` 获取 `.exe` 所在目录拼接路径，严禁直接读写相对路径 `"config.json"`。原因：程序通过清单申请管理员权限（UAC）启动时，Windows 会将进程的默认工作目录（CurrentDirectory）强制重置为 `C:\Windows\System32`，用相对路径会把配置写进系统目录甚至报错触发兜底。
- 位置说明：配置跟着程序走，整个文件夹拷到另一台机器，集群名单和根目录等普通设置原样带过去；凭据内容例外，拷过去也解不开，见 8.3 和第 9 节。
- 格式：UTF-8 编码的 JSON 纯文本，序列化使用系统自带的 `DataContractJsonSerializer`，严禁引入第三方包。用记事本打开就能看、就能改普通设置；凭据内容在文件里只是密文，见 8.3。
- **只读目录兜底：** 若 `.exe` 被放在无写入权限的受保护目录导致同目录写入失败，自动回退读写至 `%LocalAppData%\InspectionWidget\config.json`，并在设置窗口底部注明当前实际生效的配置文件路径。
- 已存在该用户回退配置时优先读取它，避免同目录后来恢复可写便读回旧配置；否则读取同目录配置（即使只读也先读），再决定写入位置。
- 一次运行只写一个权威位置，切换位置成功写入前保留原件；两个位置都不可写时明确标注“设置未保存”，不得声称根目录已经记住。
- 以当前进程实际 Windows 身份读写，UAC 使用其他管理员账号启动时不视为原桌面账号。
- **损坏自愈：** 配置缺失按首次初始化处理；缺少可选字段仅补默认值，不清空有效设置。语法或结构损坏时先备份原件（备份为 `config.corrupt.时间戳.json`），再加载默认值并提示；备份失败不得覆盖原件。权限或磁盘读取失败应提示并保留文件，不能当成坏配置覆盖。仅个别凭据条目的密文无法解密时（如跨机拷贝引起），仅将该条目标记为“需重新设置”，不影响集群名单等其他配置正常加载。
- **写入互斥：** 配置写入用同目录唯一临时文件加原子替换；以权威配置路径为粒度跨会话互斥，避免共享该文件的进程互相覆盖，无法取得锁时不写入。

### 8.3 凭据按钮怎么存：不能明文

凭据条目里存的是账号、密码类内容，如果在 `config.json` 里明文保存，谁拷走这个文件，内容就全漏了。零依赖下有系统自带的解法：

- **加密方式：** 使用 Windows 自带的数据保护接口 DPAPI（`System.Security` 中的 `ProtectedData`），不需要安装任何东西，与零依赖定位不冲突。
- **绑定范围：** 加密作用域为 `DataProtectionScope.CurrentUser`，绑定当前机器的当前 Windows 登录账号。密文只能在同一台机器、同一个 Windows 账号下解开；文件被拷到别的机器或别的账号，解不开。通常只有相同 Windows 用户且同机可解密，但域漫游配置等存在跨机例外；同一用户下的其他进程也可能调用 DPAPI 解密。它保护静态配置，不构成对同账号恶意程序的隔离。
- **文件里的形态：** 原文按 UTF-8 转字节、经 `ProtectedData.Protect` 加密后转为 Base64 文本写进 `config.json`，记事本打开也只能看到一串乱码，看不到原文。
- **设置界面防窥：** 内容输入框用密码掩码（●）显示，不回显原文。已配置过内容的条目，打开设置时仅显示占位提示（已加密保存，直接输入新内容可覆盖，留空不修改；删除该条目即删除其内容），不提供查看明文功能。
- **按需内存解密：** 只有点击主面板凭据按钮时，程序才在内存中实时解密并写入剪贴板，全程不落盘、不写日志。
- **30 秒自动清空剪贴板：**
  - 设置里提供“复制后 30 秒自动清空剪贴板”开关（默认开启）。只清理本次写入且之后未变更的剪贴板版本：复制成功时记录序列号（`GetClipboardSequenceNumber`）与本次令牌，并启动（或重置）30 秒倒计时定时器——连续点击不同凭据时必须重置定时器，避免旧定时器提前触发清掉刚复制的内容。SHA256 哈希可保留作辅助。
  - 30 秒后在同一次剪贴板加锁期间复核版本再清空；即使新内容文字相同，也不能误清。版本不一致，说明期间已复制了其他内容，程序不做干预。
  - 写入凭据时设置 Windows 的禁止历史与云同步格式（`CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 置否），但不能约束第三方程序。
  - **退出兜底：** 若在 30 秒倒计时期间关闭程序，程序在退出前（`FormClosing`）立即执行一次同样的版本核对，若剪贴板里仍是刚复制的凭据，立即清空后再退出，防止密码永久残留在剪贴板。

### 8.4 集群与凭据的增删改

- 在设置窗口里增删集群、修改名称、上下调整顺序，点击“保存”后主面板立即动态刷新布局，不需要重启程序。集群名保存时校验：不可为空或纯空格，且不得包含 Windows 文件名非法字符（`\ / : * ? " < > |`）及控制字符，不合法直接弹窗拦截，不等到截图时才报错。加载手改配置也走同一校验；最终路径须位于日期目录内，并校验追加序号后的完整路径长度。
- **凭据同样按列表增删：** 在设置窗口的凭据管理里像集群一样增删条目——添加新条目、删除已有条目、修改条目的名称与内容，上限 10 条，下限 0 条。点击“保存”后主面板立即按新的条目数重新渲染凭据区，窗口高度随条目数变化（按第 4 节的底边锚定规则伸缩），不需要重启程序。新增条目须同时填好名称与内容才计入已配置条目。
- **凭据区的渲染口径：** 主面板凭据区只渲染已配置的凭据条目，不预留空槽、不显示置灰占位。条目数为 0 时只显示分区标题与一行「未设置凭据，去设置添加」的提示行。已配置但解密失败的条目（密文解不开，属已配置条目的异常状态，与空槽无关）显示「需重设」，可点击并提示去设置中重新填写；在设置中删除某条目后，面板上对应按钮随之消失，高度随之收缩。
- 设置窗口另提供高级选项：“复制后 30 秒自动清空剪贴板”开关（默认开启）、“截图模式”选项（自动 / 仅屏幕拷贝），并在底部显示当前实际生效的配置文件路径。
- 首次启动尚无配置时，默认初始化两个示例集群（“集群1”、“集群2”），并按 7.3 弹窗引导选定保存根目录，不要给一个空面板让人猜。
- 删除集群只删名单，绝不删除磁盘上已保存的历史截图文件。

## 9. 分享给别人

分享方式已定案：只分享 `.exe` 本体，不做配置导出、不做模板导出功能。

- **对方拿到 exe 就能用：** 双击后按他自己的环境走首次流程——以管理员身份确认启动、自己选保存根目录、自己加集群、自己按需添加凭据条目（最多 10 条）。本机使用者的任何设置都不会跟过去。
- **密码天然出不了门：** 就算有人拿到的不是 exe、而是正在使用的整个程序文件夹，`config.json` 里的凭据内容是 DPAPI 密文，绑本机的 Windows 账号，在他的机器上解不开，程序只会提示那几项“需重新设置”。域漫游等例外见 8.3。
- **仍要守的规矩：** 不要直接把自己在用的整个文件夹发给别人。密文虽然解不开，但集群名、按钮名、根目录路径在配置里是明文，属于工作信息，没必要给人看。分享时只发 exe 一个文件即可。
- **对方的凭据归对方：** 对方在他自己机器上填的凭据，用他自己账号的 DPAPI 加密，和本机互不相通、互不影响。

## 10. 已知限制，先说在前面

以下限制来自 Windows 系统机制，不是程序写得好就能绕开的，提前知情比事后返工好：

- **受保护内容（DRM / 安全桌面）截不到：** 播放受版权保护视频的窗口、Windows 安全中心/UAC 弹窗等，系统底层会直接屏蔽画面输出黑图，属系统安全机制，无解。
- **个别特殊渲染窗口：** 绝大多数浏览器和软件在 `PrintWindow(PW_RENDERFULLCONTENT)` 下均可正常后台截图；极少数使用特殊显卡独占接口的软件若截出黑图，程序会自动回退为“置前窗口 + 屏幕拷贝”，此时目标窗口会短暂跳到最前。黑图或同色采样只表示可疑，无法证明系统保护、识别旧画面或判断内容完整；合法纯色窗口须提供预览确认后保存的入口。
- **权限已对等，但有弹窗代价：** 组件已定案以管理员身份启动，这可改善普通提升权限窗口的访问，但不保证截取安全桌面、SYSTEM 进程或受保护内容；UAC 提示受系统策略影响，不能用管理员启动承诺绕过所有隔离。代价是每次打开多一步系统确认弹窗。
- **剪贴板副本：** 剪贴板历史、云同步及第三方剪贴板管理器可能留副本。
- **凭据密文不可迁移：** 换机器、换 Windows 账号、重装系统后，原来的凭据按钮内容解不开，需要重新设置。这是 DPAPI 的设计，换来的正是拷走文件也漏不了密码。
- **远程桌面里套远程桌面：** 在远程桌面会话内须实测，断开、锁屏或会话切换时不承诺可截图；但如果目标窗口本身是另一层远程画面的内容，截到的就是那一层画面，这符合预期，不算故障。
- **全屏独占程序：** 游戏式全屏独占窗口可能截不到或截到桌面。日常巡检软件极少用这种模式，第一版不专门处理。

## 11. 非功能要求

- **体积：** 单个 exe 控制在 300 KB 以内量级，不捆绑任何额外文件（配置文件为运行后生成，不算捆绑）。
- **启动与响应：** 双击并通过管理员确认后 1 秒内出现面板；正常目标的截图与保存以半秒左右为性能目标；阻塞窗口、慢盘和失败回退单独记录耗时，不作为保证。UI 必须保持可取消，不能在 UI 或钩子线程执行同步截图和文件 I/O。
- **不联网：** 程序不访问网络，不自动更新，不上传任何数据。截图只存在本机指定目录，凭据只存在本机加密配置里。用户若选择 UNC、映射网络盘或同步目录，文件访问可能产生网络流量或同步副本。
- **不写注册表、不装服务、不开机自启：** 不修改系统设置，不随系统启动；需要时手动双击打开，不想用了直接关掉。
- **可卸载性：** 配置、备份、日志、暂存图和历史截图由使用者决定是否删除，设置中列出实际使用位置，不承诺只删 exe 就没有残留。
- **稳定性：** 严格管理 GDI 句柄与位图内存释放，连续截图数百张不崩溃、内存占用平稳；任何保存失败必须给出明确提示，绝不静默吞错、绝不假装成功。

## 12. 后续可以加什么（第一版不做）

以下功能有实际价值，但都会扩大第一版范围，先记下来，跑顺第一版后再按需要逐个加：

- 全局快捷键：不点面板，按快捷键直接截当前活动窗口到上次选中的集群。
- 区域截图：在窗口截图之外，支持拖框截任意矩形区域。
- 截图备注：保存后弹一个小输入框，给这张图加一句备注并写进同名文本文件。
- 一键打包：把当天全部截图打包成一个压缩文件，方便发送或归档。
- 连续截图：同一个窗口定时自动截图，用于观察一段时间内的变化。
- 截图进剪贴板：保存文件的同时把图放进剪贴板，方便立刻粘贴到文档或聊天里。这与第 3.2 节的凭据复制是两回事，不要混淆。

明确不做的两项，不要再当扩展捡回来：开机自启（已定案手动打开）、配置或模板导出（已定案只分享 exe 本体）。

## 14. 验收清单（交付前必测）

本稿已终审定稿，按本稿开发第一版、交付单个 exe 文件。开发完成后，按以下 7 项逐一实测通过后方可交付；开发过程中如需偏离本稿，先改稿再改程序，保证手里始终有一份与成品一致的说明。

1. **遮挡测试：** 目标窗口被其他普通窗口遮挡一半时，点击未遮挡部分，检查生成的 PNG 是否为完整无遮挡窗口且四周无透明黑边。
2. **缩放测试：** 在 Windows 显示缩放设为 125% 或 150% 的机器上截图，检查图片分辨率是否清晰、完整，无裁剪偏移。
3. **副屏测试：** 将目标窗口拖到副显示器（含左侧负坐标副屏）上截图，检查能否正常识别并完整截取。
4. **最小化与无效点击测试：** 待截图状态下点击小组件自身、桌面、任务栏，或按 Esc 键，检查是否按规则忽略或取消，且目标窗口按钮未被误触。
5. **管理员窗口测试：** 打开一个以管理员身份运行的命令提示符或管理工具，对其截图，检查能否正常拦截点击并完成截图。
6. **重名顺延测试：** 同一天对同一集群连续截 3 张图，检查是否依次生成 `集群名.png`、`集群名-1.png`、`集群名-2.png`。
7. **凭据加密与清空测试：** 配置凭据后打开 `config.json` 检查是否为 Base64 密文；点击复制后等待 30 秒（或直接关闭程序），检查剪贴板是否自动清空。
