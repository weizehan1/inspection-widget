# 巡检截图小组件开发步骤（后端）

> 版本：v0.2 审计修订稿 · 日期：2026-11-02
> 配套文档：《巡检截图小组件白皮书》v0.3。本文件只回答「后端按什么顺序、做成什么样、怎么验收」，不重新讨论需求；需求有冲突时以白皮书为准，本文件随白皮书同步修订。

## 1. 文档范围与当前状态

- **凭据按钮数量：10 个。** 两份文档统一按 10 个执行；未设置的按钮保留并置灰。
- **当前状态：** 私有仓库已建立，目前只有设计文档，没有工程、源码、测试或 exe。本文件的步骤与验收均是后续计划。
- **前端不在本文件范围内。** 界面视觉稿走 Figma 设计流程单独出图，你看图定版后，后端在阶段 2 和阶段 7 按定版稿对齐控件布局与配色；在此之前，后端先用朴素控件把功能跑通，不等图、不阻塞。

## 2. 总览：十个阶段，一关一关过

开发按依赖顺序拆成阶段 0 到阶段 8，外加阶段 9 的源码托管。原则是：**每阶段有明确交付物和过关标准，上一阶段没过关，不进下一阶段**，避免最后所有问题挤在一起排查。

| 阶段 | 内容 | 交付物 | 粗估工时 |
| --- | --- | --- | ---: |
| 0 | 开发环境与工程骨架 | 能以管理员身份弹出的空面板 exe | 0.5 天 |
| 1 | 配置层 | `config.json` 读写与自愈模块 | 0.5 天 |

## 3. 阶段 0：开发环境与工程骨架

目标：在一台 Windows 开发机上，把「双击 exe → 弹 UAC 确认 → 出现一个空面板」的链路先跑通。

具体步骤：

1. 开发机准备 Visual Studio 2022（版本选择遵守其许可）及「.NET 桌面开发」工作负载、.NET Framework 4.8 目标包；统一使用 MSBuild / VS Release 构建，不把系统旧版 `csc.exe` 当成等价构建环境。安装开发工具另行授权，不因本计划自动执行。
2. 新建 WinForms 项目，目标框架固定 **.NET Framework 4.8**，目标机须具备 4.8+；Windows 10 早期版本和 Server 须另查。项目关闭「首选 32 位」，平台选 Any CPU；全部句柄与指针用 `IntPtr` / `UIntPtr`，不能靠平台选项补救截断。发布清单记录实测的系统版本与位数。
3. 加入应用清单文件 `app.manifest`，写死两件事：
   - `requestedExecutionLevel` 设为 `requireAdministrator`，实现默认管理员启动；
   - 声明 DPI 感知（`PerMonitorV2` 优先），这是阶段 4 截图不发虚、不偏的前提，必须在第一天就声明好，后补容易漏测。
4. 引用的程序集全部限定为 .NET Framework 自带：`System.Windows.Forms`、`System.Drawing`、`System.Security`（DPAPI 用）、`System.Web.Extensions` 或框架自带的 JSON 序列化能力。**不引入任何 NuGet 第三方包**，这是零依赖的硬线；JSON 读写宁可用框架自带的 `JavaScriptSerializer` / `DataContractJsonSerializer`，也不引 Newtonsoft.Json。
5. 建好源码目录骨架（与阶段 9 的仓库结构一致）：

```text
InspectionWidget/
├─ InspectionWidget.sln
├─ src/
│  ├─ InspectionWidget.csproj  工程与框架引用、嵌入 manifest
│  ├─ Program.cs          入口、全局异常兜底挂载
│  ├─ MainForm.cs         主面板
│  ├─ SettingsForm.cs     设置窗口
│  ├─ Config/             配置模型与读写（阶段 1）
│  ├─ Capture/            选窗与截图（阶段 3、4）
│  ├─ Storage/            保存与命名（阶段 5）
│  ├─ Credentials/        DPAPI 与剪贴板（阶段 6）
│  └─ Native/             全部 Win32 P/Invoke 声明，集中一处
├─ app.manifest
├─ .gitignore
└─ README.md
```

过关标准：Release 编译出的单个 exe 拷到另一台没装开发环境的 Win10/11 机器上，双击弹管理员确认、确认后 1 秒内出现空面板，任务管理器里确认进程为高权限。

## 4. 阶段 1：配置层先行

目标：把 `config.json` 的模型、读写和自愈做完并单测过，后面所有模块只调这一层，不各自碰文件。

配置模型（字段与白皮书第 8 节一一对应）：

| 字段 | 内容 | 备注 |
| --- | --- | --- |
| `RootPath` | 截图保存根目录 | 首次为空，空即触发阶段 2 的选目录流程 |
| `Clusters` | 集群名列表（含有序） | 6–10 个量级，不设硬上限 |
| `Credentials` | 10 个凭据位：按钮名 + DPAPI 密文（Base64） | 密文阶段 6 才填，本阶段先定结构 |
| `AutoClearClipboard` | 复制后 30 秒自动清空开关 | 默认关 |
| `CaptureMode` | 截图抓法偏好：自动 / 强制 PrintWindow / 强制 BitBlt | 默认自动 |
| `WindowLeft`、`WindowTop` | 面板上次位置 | 下次打开还原 |
| `LastCluster` | 上次选中的集群名 | 仅恢复视觉选择，打开时仍为待命，不自动挂钩 |
| `CredentialsCollapsed` | 凭据区是否折叠 | 分区切换后持久化，重开保持 |

具体步骤：

1. 默认使用 exe 同目录的 `config.json`；回退位置固定 `%LocalAppData%\InspectionWidget\config.json`。已有回退配置优先读取，否则先读取同目录配置，再判断能否写入。只读配置仍可加载；不得因可写性变化读回旧配置。运行中只认一个权威位置并显示实际路径；回退写入成功前保留原件，两处均不可写时提示“设置未保存”。当前进程实际账号决定 DPAPI 与用户目录，UAC 换账号启动须在验收中单独记录。
2. 先在目标目录写唯一临时文件，完成刷新、关闭后用原子替换提交（首次创建用不覆盖的移动）；失败保留原正式文件并提示，不先删除正式文件。读取配置前按规范化的权威配置路径取得跨会话互斥或进程生命周期文件锁，覆盖所有访问同一配置的实例，不能仅按用户名或会话隔离锁；锁占用或权限不足时提示并停止配置写入，不切换路径绕过。原子替换防止半写，互斥防止旧设置覆盖新设置，两者都需要。
3. 文件缺失为正常首次初始化，不存在“备份缺失文件”；可选字段缺少时仅补默认值。语法或结构损坏先以不重名方式备份，再载默认值；备份失败不得覆盖原件。读取权限或 I/O 故障提示并保留文件，不按损坏配置重置。根目录确实遗失时明确提示恢复配置或重选，不能谎称已保存。
4. 单条凭据密文损坏或解不开时，只把那一位标记为「需重新设置」，不连累其他配置整体重置；配置读取不需解密全部凭据，按钮点击时再解密。
5. 集群名在设置保存与配置加载时统一校验：非法字符、控制字符、空名、`.` / `..`、尾部点或空格、Windows 设备保留名（含带扩展名形式），按 Windows 大小写不敏感规则查重；最终保存时检查目录包含关系和带序号的路径长度。无效项提示修正，不默默替换后覆盖历史图。

过关标准：分别验证首次缺文件、缺少可选字段、乱码、字段类型错误、只读配置、回退目录重启、同目录恢复可写、备份失败、同会话及跨会话双实例（含共享配置的不同账号）。有效字段不丢失；有坏文件才备份；无法保存时明确提示且原件不变；已持久化的根目录重启不再主动询问。

## 5. 阶段 2：主窗口与面板状态机

目标：面板的「形」先立住——位置、置顶、最小化、状态切换都对，按钮先摆占位，点击逻辑留给后续阶段接。

具体步骤：

1. 窗体设为无边框或细边框、`TopMost` 置顶，首次启动定位到主显示器工作区右下角（任务栏上方）；之后按配置里记的位置还原，位置越界（比如拔掉副屏）时自动收回主屏可见范围。
2. 最小化只做一件事：缩到任务栏。`ShowInTaskbar` 保持开启，不建托盘图标、不写托盘菜单；点任务栏图标按系统默认行为还原，不额外写代码干预。
3. 面板内容自上而下排：顶部行（程序名、当天日期、设置、最小化；不放根目录）→ 集群按钮列（一列竖排，6–10 个）→ 凭据分区标题行（不用细分隔线）→ 可折叠凭据区（10 个、2 列网格，只显示按钮名，折叠状态持久化）→ 底部两行（反馈一行、保存根目录常驻一行；点击根目录行打开今日文件夹）。反馈消失不隐藏根目录行。
4. 面板用统一状态机管理操作；短暂提示是独立显示层，不用提示状态替代业务状态：
   - **待命：** 默认态，集群按钮可点，凭据按钮可点；
   - **待截图：** 点了某个集群后进入，高亮该集群并提示「请点击要截图的窗口」，Esc 或再点一次该集群回到待命；
   - **处理中：** 选窗完成后卸载输入钩子，固定本次集群、根目录、采集日期和请求编号，再异步截图与保存；禁用新截图及凭据操作，防止重复请求或误操作。失败且尚未落盘时保留当前图供重试，离开前显式确认放弃；旧请求的迟到结果不得改变当前状态。
   - **提示层：** 保存或复制成功后约 2 秒显示结果，提示消失不改业务状态；截图成功后业务态回待命。重开只恢复上次集群的视觉选择。
5. 首次启动且 `RootPath` 为空时，先弹文件夹选择框；用户取消则明确提示「未选目录，截图暂不可用」并在面板上保留一个「选择保存目录」入口，不许默默用某个默认路径把图存到不明处。

过关标准：面板开机手动打开后停在右下角且不被其他窗口盖住；最小化、任务栏还原、拖动后重开位置记忆、状态转换、重复点击保护、凭据区折叠与重开记忆，全部符合白皮书第 4 节描述。本阶段只验形态，视觉配色等前端定版稿（见第 1 节）。

## 6. 阶段 3：选窗——第二下点到的是哪个窗口

目标：在待截图状态下，使用者点屏幕任意位置，程序能准确说出「他点的是哪个顶层窗口」，并且这一下点击不真的落到目标程序上。

具体步骤：

1. 待截图时在独立且有消息循环的线程安装 `WH_MOUSE_LL`，保持委托存活；钩子只做坐标、顶层句柄及排除判定，立即返回。标题读取、截图、磁盘操作不在钩子或 UI 线程做，禁止把重活派回 UI 线程。
2. `WindowFromPoint` 后用 `GetAncestor(..., GA_ROOT)` 取顶层窗口。派发工作时携带请求编号、句柄与进程身份，执行前复核窗口仍存在且没有最小化或被替换；标题只作提示，不参与命名。
3. 排除桌面、各显示器任务栏及本进程所有窗口；这些点击正常放行且不触发截图。再次点已选集群由组件自己处理取消；点其他面板操作时先结束选窗再执行对应操作。
4. 对有效目标配对吞掉 `WM_LBUTTONDOWN` 与 `WM_LBUTTONUP`，收到抬起后再卸载鼠标钩子并开始截图。不要只吞按下却把抬起送给业务窗口。若按下后取消或超时，停止接受新选择，但仍配对处理该次抬起后退出；不补发点击。安装失败提示并回待命。
5. 最小化窗口不能直接靠任务栏图标选到；任务栏按第 3 条排除。已选目标在截图前最小化则提示「该窗口已最小化，请先打开」并结束本次请求。
6. 无焦点时 Esc 仍须可取消：只在选窗期间挂 `WH_KEYBOARD_LL` 处理 Esc，退出后卸载，不记录其他键；无有效选择 30 秒超时退出。退出、异常和取消都保证钩子释放，已吞下的左键按下按第 4 条收尾。

过关标准：记事本、浏览器、资源管理器和巡检客户端各点一轮；用消息测试窗口确认目标既未收到此次按下，也未收到此次抬起。点自身不误截且可再次点集群取消；桌面、任务栏可正常操作；目标获得焦点后 Esc 仍有效。补测按住左键时取消、超时、目标退出和安装失败，退出后鼠标键盘正常。

## 7. 阶段 4：截图引擎——整个开发最难的一段

目标：给定一个顶层窗口句柄，稳定产出一张完整、不黑、不虚、不带多余阴影边的内存位图。这一阶段按白皮书 6.2 的组合策略做，不许只实现一种抓法就往下走。

具体步骤：

1. **分清两种矩形：** 在 DPI 感知上下文中分别取 `GetWindowRect` 与 DWM `DWMWA_EXTENDED_FRAME_BOUNDS`。PrintWindow 按完整窗口矩形建图，再按两矩形差值裁到可视边界；BitBlt 直接用可视边界。DWM 查询失败时使用经校验的窗口矩形并注明可能含透明边，不对空、反向或异常大矩形分配位图。
2. **PrintWindow 放工作线程：** 自动模式先尝试完整窗口渲染（不设置仅客户区标志；`PW_RENDERFULLCONTENT` 的目标兼容性单独实测）。它是同步阻塞调用，不能在 UI 或钩子线程调用。超时使请求失效，可用另一张独立位图回退 BitBlt；原调用未返回前不启动新的 PrintWindow，不释放或复用其 DC / 位图，返回后丢弃迟到结果并释放。不能把 `Task` 等待超时写成“底层调用已取消”。
3. **采样是启发式：** 检查 API 返回值并采样黑色、同色或明显空白区域；采样不能证明画面正确或最新，也不能证明受系统保护。可疑图先提示或回退；合法纯色图允许预览确认后保存，不自动保存可疑图，不承诺采样一定半秒完成。
4. **BitBlt 回退：** 自动模式在 PrintWindow 失败、超时或可疑时尝试；强制 PrintWindow / 强制 BitBlt 不切换方法。临时隐藏组件，尝试 `SetForegroundWindow`，核对结果、目标矩形与遮挡；禁止靠 `BringWindowToTop` 假定必然成功。无法取得无遮挡且完整在显示器联合区域内的画面时，提示用户调整后重试，不保存混有遮挡物的图。恢复组件显示与置顶状态；不强行模拟点击或绕过前台限制。
5. **DPI 校准：** PerMonitorV2 与 WinForms 的 DPI 初始化在首个窗口句柄创建前完成。两种矩形统一按物理像素计算，DWM 边界不再乘一次缩放率；保留负坐标，跨屏按矩形尺寸建图。截图前后窗口移动或尺寸变化则使本次结果失效，提示重试。
6. **特殊窗口：** 对受保护内容、独占全屏或硬件加速软件如实提示可能不兼容；不得仅凭黑色采样断言原因。迟到结果、取消请求、失败路径与 DC / GDI 对象都须按所有权释放。

过关标准：在遮挡、无遮挡、负坐标副屏、150% 缩放、最大化、普通窗口化下逐项留图核对；补测跨屏不同缩放、纯色合法窗口、目标移动、置前被拒、组件遮挡、窗口部分出屏、PrintWindow 阻塞。能正确抓取的图完整清晰，无法保证的明确失败；UI 不挂死，不产生无限工作线程或迟到保存。

## 8. 阶段 5：保存与命名

目标：把阶段 4 的内存位图按白皮书第 7 节规则稳妥落盘，一张都不许丢、一张都不许覆盖错。

具体步骤：

1. 每次请求在采集开始时读取一次系统日期，固定集群名、根目录与日期，保存为 `RootPath\yyyy-MM-dd\`，落盘重试沿用本次日期；下一次采集重新读取。跨午夜时同一张图不因保存耗时改归属，不改生产机系统日期做验收。
2. 从 `集群名.png`、`集群名-1.png` 起，使用 `FileMode.CreateNew` 原子占用第一个可用名称；只对确定的重名冲突顺延，其他 I/O 故障直接进入兜底。对并发重名设有界重试并可取消，不可无限循环。编码、刷新和关闭全部成功才提示完成；异常时只清理本请求创建的不完整文件，不能删除或覆盖原文件。
3. 格式只存 PNG（`ImageFormat.Png`），不提供 JPG 选项，理由同白皮书 6.3：文字和表格线条不能糊。
4. 写入失败兜底：根目录所在磁盘不可用、无写入权限时，优先暂存 `程序目录\pending\日期\`，失败再试 `%LocalAppData%\InspectionWidget\pending\日期\`，均按不覆盖规则写入。成功提示“已暂存”及实际路径；全部失败则保留当前内存图并提示“尚未保存”、允许重试或显式放弃，不能接收新截图把它覆盖。
5. 保存成功后回填两件事：提示实际保存路径；暂存时提供打开暂存位置的入口。另保留「打开今日文件夹」，目标尚不存在时只提示“今天尚无截图”，不为打开目录制造空日期文件夹。

过关标准：同一集群连截 3 张，落盘为 `集群名.png`、`集群名-1.png`、`集群名-2.png` 且内容互不覆盖；用可注入时钟或隔离测试机验证跨天第一张重置与跨午夜归属；模拟同名竞争、写入中断、根目录离线和两级暂存均不可写。原图哈希不变，未落盘图可重试，暂存提示准确。

## 9. 阶段 6：凭据模块——10 个按钮，DPAPI 加密

目标：10 个凭据位从设置、存储到点击复制全链路走通，且任何环节看不到明文落盘。

具体步骤：

1. 加密调用 `ProtectedData.Protect`，范围固定 `DataProtectionScope.CurrentUser`，可选熵（附加口令式盐值）第一版不加——加了就得多管一个秘密，收益不大；明文先转 UTF-8 字节再加密，密文字节转 Base64 写进配置的对应凭据位。
2. 解密只发生在点击按钮的那一瞬间：`Unprotect` 后直接写剪贴板，明文不写日志、不进状态提示、不落任何临时文件。解密抛异常（配置从别的机器拷来、换了 Windows 账号等）时提示「该凭据需重新设置」，不崩溃。
3. 在 STA 线程写入 Unicode 文本及 Windows 的 `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 禁用标志。使用同一次 `OpenClipboard` 锁保护写入、令牌与 `GetClipboardSequenceNumber` 记录，不能 `Clipboard.SetText` 释放锁后才读取序列号，以免记录到别人新写的版本；异常只有限重试，失败不提示“已复制”。第三方管理器仍可能读取，见白皮书第 10 节。
4. 自动清空：`AutoClearClipboard` 开启时，复制后起一个 30 秒计时；再次复制成功后替换旧任务；到点在同一次 `OpenClipboard` 锁内核对序列号和本次令牌，仍是本次写入且未变更才 `EmptyClipboard`，`finally` 释放锁。无法加锁或无法可靠核对时跳过并提示，不冒险清空；同文字的新复制也不得清除。退出或关闭开关时取消任务；不声称能清除历史、云端或第三方副本。
5. 面板凭据区固定渲染 10 个位：已设置的显示按钮名可点，未设置的保留并置灰；按钮上永远只显示名字，不显示内容任何片段。

过关标准：填满 10 个凭据逐个点一遍，粘贴结果与原文一致；用记事本打开 `config.json` 全文搜索任一凭据原文，搜不到；把整个程序文件夹拷到另一台机器（或另一个 Windows 账号）打开，在无漫游配置的独立账号环境中凭据提示需重新设置、程序其他功能正常；域漫游例外单独记录，不能把跨机失效作为普遍保证；开启自动清空后复制凭据、30 秒内改复制别的内容，到点后剪贴板里是新内容未被误清；另测新内容与旧文字相同、连续复制凭据、关闭开关、剪贴板被占用及退出场景。

## 10. 阶段 7：设置窗口

目标：所有需要人维护的东西都收进一个设置窗口，改完保存立即生效，不重启程序。

设置窗口分四组，一组一块，不做多页签：

1. **集群：** 列表形式增删、改名、上下移排序；改名走阶段 1 的非法字符校验；删集群只删名单，明确提示不删历史截图。
2. **保存位置：** 显示当前根目录全路径，提供「更改」按钮弹文件夹选择框；同时显示配置文件的实际存放路径（含阶段 1 回退到 `%LocalAppData%` 的情况），让使用者心里有数文件在哪。
3. **凭据（10 个）：** 每行一个凭据位——按钮名输入框 + 内容输入框 + 状态字样。内容框用密码掩码字符显示且不回显已存原文：已设置的只显示「已设置」，要改就清空重填覆盖，留空保存表示不改动原内容，另设「清除」动作把该位清空。**不提供查看原文的入口**，这是硬规矩，不因方便破例。
4. **选项：** 「复制后 30 秒自动清空剪贴板」开关、截图抓法偏好（自动 / 强制 PrintWindow / 强制 BitBlt），后者用于个别顽固软件单独处理。

保存动作统一走阶段 1 的配置层落盘，成功后刷新主面板的集群列与凭据区；校验不过关时停留在设置窗口并指出哪一项有问题，不许带着错误配置关窗。

过关标准：在设置里把集群从增删改排走一整轮、换一次根目录、改一个凭据、拨一次自动清空开关，主面板不重启全部即时生效；故意填一个带斜杠的集群名，被当场拦下。

## 11. 阶段 8：异常兜底、打包与实测验收

目标：把「演示能跑」变成「天天能用」，并产出可交付的单个 exe。

具体步骤：

1. 入口处挂全局异常处理（UI 线程与非 UI 线程各一处）：未预料异常只记到程序目录下的 `error.log`（只记异常类型、时间与操作环节，**绝不记凭据明文和截图内容**），界面给一句人话提示，日志目录不可写时回退 `%LocalAppData%\InspectionWidget`，再失败则仅界面提示，避免异常处理再次抛错。UI 可恢复异常回待命或保留待保存图；非 UI 未处理异常和不可恢复错误提示后退出，不承诺挂全局处理就能继续安全运行。
2. 资源纪律：每次截图的位图、图形对象用完即释放；钩子、计时器在状态退出时成对卸载。连续截图 100 张内存无明显上涨，作为本阶段的硬指标实测。

## 12. 阶段 9：源码上 GitHub——建私有库

目标：源码进现有 GitHub 私有仓库，具备可重现构建步骤。当前只有文档，尚不可编译；开发后记录工具版本、构建命令和产物哈希，不把“可构建”等同于字节完全一致。

### 12.1 建库

1. 仓库已为 [`weizehan1/inspection-widget`](https://github.com/weizehan1/inspection-widget)，2026-11-02 核对可见性为 **Private**，不重复建库。这个工具涉及巡检场景与集群命名习惯，源码和提交记录都不公开，没有商量余地。
2. GitHub 连接器已可读取该仓库元数据；日常开发使用本机 git 检出、测试、提交与推送，远程写入后回读提交及文件。不把某个连接器的能力描述为固定的“快照式推送”限制。

### 12.2 入库前先立规矩：什么绝不能进仓库

`.gitignore` 第一次提交前就写好，至少排除：

- `config.json` 及其备份、损坏备份文件——里面有根目录路径和 DPAPI 密文，密文也属于需保护的本地内容，不能进仓库；
- `error.log`、截图产物（`*.png`）、日期文件夹；
- 编译产物：`bin/`、`obj/`、`.vs/`、`*.user` 等 Visual Studio 本地文件。

仓库只放源码、工程与清单、设计文档、测试与构建说明；不放实际运行数据。`.gitignore` 不能移除已被跟踪的敏感文件，发现后须单独报告与处置，不能把新增忽略规则当成历史清理。README 写清三件事：这是什么、怎么编译（VS 2022 + .NET Framework 4.8）、怎么运行（双击 exe、首次选目录）。第一次提交前用 `git status` 逐项核对暂存区，确认没有把本机在用的 `config.json` 带进去，这一步不能省。

### 12.3 推送与后续节奏

1. 从现有仓库 `git clone` 后在独立分支开发，首次工程提交把阶段 0 的骨架推上去，之后**每过一个阶段推一次**，提交信息按阶段写（如「阶段 4：截图引擎，PrintWindow + BitBlt 回退」），出问题能按阶段回退，不攒大包一次性提交。
2. 主分支只放能编译、能运行的代码；阶段 4 这种高风险段落可以先开分支试验，验收矩阵过了再合回主分支。
3. 每个对外可用的版本打一个标签（如 `v1.0`），并把该标签编译出的 exe 与标签对应关系记在 README 的版本记录里；分享给别人时（白皮书第 9 节：只发 exe 本体）发的就是某个标签对应的 exe。
4. 推送完成后用官方连接器读回仓库文件列表与最近提交各核对一次，确认远程与本地一致，再把仓库链接记入交付说明，才算本阶段过关。

过关标准：在另一台机器（或干净目录）克隆该私有仓库，按 README 操作能成功编译出可运行的 exe；被跟踪文件不包含真实配置、日志或截图，内容检查无实际凭据；文档中出现 `config.json` 文件名或示例不算泄露。
