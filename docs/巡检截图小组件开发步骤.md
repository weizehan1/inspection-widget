# 巡检截图小组件开发步骤（后端）

> 版本：v0.1 · 日期：2026-11-02
> 配套文档：《巡检截图小组件白皮书》v0.2。本文件只回答「后端按什么顺序、做成什么样、怎么验收」，不重新讨论需求；需求有冲突时以白皮书为准，本文件随白皮书同步修订。

## 1. 先说清两处与白皮书的差异

- **凭据按钮数量：10 个。** 白皮书 v0.2 写的是 5 个，你最新已改定为 10 个。本文件全部按 10 个写，白皮书下次修订时同步改这一处。
- **前端不在本文件范围内。** 界面视觉稿走 Figma 设计流程单独出图，你看图定版后，后端在阶段 2 和阶段 7 按定版稿对齐控件布局与配色；在此之前，后端先用朴素控件把功能跑通，不等图、不阻塞。

## 2. 总览：十个阶段，一关一关过

开发按依赖顺序拆成阶段 0 到阶段 8，外加阶段 9 的源码托管。原则是：**每阶段有明确交付物和过关标准，上一阶段没过关，不进下一阶段**，避免最后所有问题挤在一起排查。

| 阶段 | 内容 | 交付物 | 粗估工时 |
| --- | --- | --- | ---: |
| 0 | 开发环境与工程骨架 | 能以管理员身份弹出的空面板 exe | 0.5 天 |
| 1 | 配置层 | `config.json` 读写与自愈模块 | 0.5 天 |
| 2 | 主窗口与面板状态机 | 右下角置顶小窗，最小化与还原正常 | 0.5–1 天 |
| 3 | 选窗 | 点中哪个顶层窗口识别无误 | 1 天 |
| 4 | 截图引擎 | 遮挡、缩放、多屏下都能抓到完整窗口图 | 1–2 天 |
| 5 | 保存与命名 | 按日期落盘、重名顺延、不覆盖 | 0.5 天 |
| 6 | 凭据模块 | 10 个按钮 DPAPI 加密复制 | 1 天 |
| 7 | 设置窗口 | 集群、根目录、凭据可视化维护 | 1 天 |
| 8 | 异常兜底、打包与实测验收 | Release 单 exe + 验收记录 | 1 天 |
| 9 | 源码上 GitHub 私有库 | 私有仓库，源码可克隆可编译 | 0.5 天 |

合计粗估 7–9 个工作日，为估算而非承诺；阶段 4 的坑最不可控，实际浮动主要出在这里。

## 3. 阶段 0：开发环境与工程骨架

目标：在一台 Windows 开发机上，把「双击 exe → 弹 UAC 确认 → 出现一个空面板」的链路先跑通。

具体步骤：

1. 开发机装 Visual Studio 2022 Community（免费版即可），勾选「.NET 桌面开发」工作负载；没有 VS 时退而求其次，用系统自带的 `csc.exe` 命令行编译，但整个开发期只选一种方式，不混用。
2. 新建 WinForms 项目，目标框架定 **.NET Framework 4.8**（4.7.2 亦可，全程统一一个，不中途换）。项目属性里关掉「首选 32 位」，平台选 Any CPU，保证在 64 位系统上取到的窗口句柄和坐标不失真。
3. 加入应用清单文件 `app.manifest`，写死两件事：
   - `requestedExecutionLevel` 设为 `requireAdministrator`，实现默认管理员启动；
   - 声明 DPI 感知（`PerMonitorV2` 优先），这是阶段 4 截图不发虚、不偏的前提，必须在第一天就声明好，后补容易漏测。
4. 引用的程序集全部限定为 .NET Framework 自带：`System.Windows.Forms`、`System.Drawing`、`System.Security`（DPAPI 用）、`System.Web.Extensions` 或框架自带的 JSON 序列化能力。**不引入任何 NuGet 第三方包**，这是零依赖的硬线；JSON 读写宁可用框架自带的 `JavaScriptSerializer` / `DataContractJsonSerializer`，也不引 Newtonsoft.Json。
5. 建好源码目录骨架（与阶段 9 的仓库结构一致）：

```text
InspectionWidget/
├─ InspectionWidget.sln
├─ src/
│  ├─ Program.cs          入口、全局异常兜底挂载
│  ├─ MainForm.cs         主面板
│  ├─ SettingsForm.cs     设置窗口
│  ├─ Config/             配置模型与读写（阶段 1）
│  ├─ Capture/            选窗与截图（阶段 3、4）
│  ├─ Storage/            保存与命名（阶段 5）
│  ├─ Credentials/        DPAPI 与剪贴板（阶段 6）
│  └─ Native/             全部 Win32 P/Invoke 声明，集中一处
├─ app.manifest
├─ .gitignore
└─ README.md
```

过关标准：Release 编译出的单个 exe 拷到另一台没装开发环境的 Win10/11 机器上，双击弹管理员确认、确认后 1 秒内出现空面板，任务管理器里确认进程为高权限。

## 4. 阶段 1：配置层先行

目标：把 `config.json` 的模型、读写和自愈做完并单测过，后面所有模块只调这一层，不各自碰文件。

配置模型（字段与白皮书第 8 节一一对应）：

| 字段 | 内容 | 备注 |
| --- | --- | --- |
| `RootPath` | 截图保存根目录 | 首次为空，空即触发阶段 2 的选目录流程 |
| `Clusters` | 集群名列表（含有序） | 6–10 个量级，不设硬上限 |
| `Credentials` | 10 个凭据位：按钮名 + DPAPI 密文（Base64） | 密文阶段 6 才填，本阶段先定结构 |
| `AutoClearClipboard` | 复制后 30 秒自动清空开关 | 默认关 |
| `CaptureMode` | 截图抓法偏好：自动 / 强制 PrintWindow / 强制 BitBlt | 默认自动 |
| `WindowLeft`、`WindowTop` | 面板上次位置 | 下次打开还原 |
| `LastCluster` | 上次选中的集群名 | 打开时恢复选中态 |

具体步骤：

1. 配置文件固定放 exe 同目录，文件名 `config.json`；启动时先探同目录可写性，不可写则回退到当前用户的应用数据目录（`%AppData%` 下以程序名建夹），并把实际路径记下来供设置界面展示。
2. 写入采用「先写临时文件、再替换正式文件」的方式，避免写一半断电或崩溃把配置写坏。
3. 读取失败（文件缺失、JSON 语法错误、字段类型不对）一律不抛给用户看堆栈：把坏文件改名备份为 `config.broken-时间戳.json`，生成默认配置，面板上给一句人话提示。
4. 单条凭据密文损坏或解不开时，只把那一位标记为「需重新设置」，不连累其他配置整体重置。
5. 集群名保存时做文件名非法字符校验（`\ / : * ? " < > |` 以及空名、重名），不过关当场拦下提示，不等截图时才报错。

过关标准：手工把 `config.json` 改出三种坏法（删文件、写乱码、删一个字段），程序三次都能正常打开、配置回到可用状态，且坏文件有备份留存。

## 5. 阶段 2：主窗口与面板状态机

目标：面板的「形」先立住——位置、置顶、最小化、状态切换都对，按钮先摆占位，点击逻辑留给后续阶段接。

具体步骤：

1. 窗体设为无边框或细边框、`TopMost` 置顶，首次启动定位到主显示器工作区右下角（任务栏上方）；之后按配置里记的位置还原，位置越界（比如拔掉副屏）时自动收回主屏可见范围。
2. 最小化只做一件事：缩到任务栏。`ShowInTaskbar` 保持开启，不建托盘图标、不写托盘菜单；点任务栏图标按系统默认行为还原，不额外写代码干预。
3. 面板内容自上而下排：顶部行（程序名、当天日期、最小化与设置入口）→ 集群按钮列（一列竖排，6–10 个）→ 分隔线 → 凭据按钮区（10 个，只显示按钮名）→ 底部行（打开今日文件夹、状态提示区）。
4. 面板内部定三态状态机，全程序只认这三态，不许各处自己记标志位：
   - **待命：** 默认态，集群按钮可点，凭据按钮可点；
   - **待截图：** 点了某个集群后进入，高亮该集群并提示「请点击要截图的窗口」，Esc 或再点一次该集群回到待命；
   - **提示：** 保存成功或复制成功后短暂显示结果（如文件名、「已复制」），约 2 秒自动回到进入前的状态。
5. 首次启动且 `RootPath` 为空时，先弹文件夹选择框；用户取消则明确提示「未选目录，截图暂不可用」并在面板上保留一个「选择保存目录」入口，不许默默用某个默认路径把图存到不明处。

过关标准：面板开机手动打开后停在右下角且不被其他窗口盖住；最小化、任务栏还原、拖动后重开位置记忆、三个状态之间切换，全部符合白皮书第 4 节描述。本阶段只验形态，视觉配色等前端定版稿（见第 1 节）。

## 6. 阶段 3：选窗——第二下点到的是哪个窗口

目标：在待截图状态下，使用者点屏幕任意位置，程序能准确说出「他点的是哪个顶层窗口」，并且这一下点击不真的落到目标程序上。

具体步骤：

1. 进入待截图状态时安装低级鼠标钩子（`WH_MOUSE_LL`），只监听左键按下；退出待截图状态（截完、取消、超时）立刻卸载钩子，不常驻监听。钩子回调里只记坐标和时间戳就返回，重活丢回主线程做，避免回调超时被系统摘钩。
2. 拿到坐标后用 `WindowFromPoint` 取最内层子窗口句柄，再用 `GetAncestor` 追溯到顶层窗口；同时取窗口标题，仅用于状态提示里让使用者确认选对了对象，不参与文件命名。
3. 排除名单写死：追溯结果是桌面、任务栏、或组件自身窗口时，本次点击忽略并保持待截图状态，不报错、不退出。
4. 拦截规则：钩子里对这次左键按下做吞掉处理（**默认不放行**），防止点在目标窗口的「关闭」「提交」上把业务操作误触发；截图完成或取消后不补发这次点击。
5. 最小化窗口处理：追溯到的窗口若处于最小化状态（`IsIconic`），不截图，提示「该窗口已最小化，请先打开」，并回到待命状态。
6. 待截图状态加一个兜底超时（建议 30 秒无点击自动回到待命），防止钩子长期挂着、使用者忘了这回事。

过关标准：拿记事本、浏览器、资源管理器、一个巡检类客户端各点一轮，提示出的窗口标题与实际点中的程序一致；点组件自己、点桌面、点任务栏都不误截；点在目标窗口的按钮上，按钮不被触发。

## 7. 阶段 4：截图引擎——整个开发最难的一段

目标：给定一个顶层窗口句柄，稳定产出一张完整、不黑、不虚、不带多余阴影边的内存位图。这一阶段按白皮书 6.2 的组合策略做，不许只实现一种抓法就往下走。

具体步骤：

1. **先取正确的矩形：** 用桌面窗口管理器接口 `DwmGetWindowAttribute` 取窗口的实际可视边界（`EXTENDED_FRAME_BOUNDS`），不用 `GetWindowRect` 的含阴影矩形；多显示器下坐标可为负数，全程用真实屏幕坐标，不做从零假设。
2. **首选 PrintWindow：** 向内存位图调用 `PrintWindow`，标志位用带客户区完整渲染的选项（`PW_RENDERFULLCONTENT`），让窗口把自己重绘出来，被遮挡的部分也能抓全。
3. **黑图检测：** 对抓到的图做采样检测——按网格取若干像素点，全黑或全同色占比超过阈值即判为失败。只判采样点、不逐像素扫描，保证半秒内出结果。
4. **回退 BitBlt：** PrintWindow 判失败且设置里的抓法不是「强制 PrintWindow」时回退：先把目标窗口短暂置前（`SetForegroundWindow` + 必要时 `BringWindowToTop`），按可视边界矩形从屏幕设备上下文 BitBlt 拷贝；截完不主动改动窗口原有层级之外的状态。
5. **DPI 校准：** 进程已在阶段 0 声明 PerMonitorV2 感知；截图时以目标窗口所在显示器的缩放比例复核位图尺寸与矩形逻辑尺寸的比值，不一致时按物理像素重算矩形再抓，不许交付发虚图。
6. **特殊窗口的预期管理：** 受版权保护内容、全屏独占程序截出黑图属系统限制（白皮书第 10 节），检测到纯黑时给明确提示「该窗口可能受系统保护，截不到画面」，不存黑图文件、不假装成功。

过关标准：验收矩阵逐格过——目标窗口分别处于「被其他窗口遮一半、完全未遮挡、在副屏上、所在屏缩放 150%、最大化、普通窗口化」六种情形下，产出图均完整且文字清晰；故意拿一个视频播放窗口测黑图路径，程序给提示且不落盘黑图。

## 8. 阶段 5：保存与命名

目标：把阶段 4 的内存位图按白皮书第 7 节规则稳妥落盘，一张都不许丢、一张都不许覆盖错。

具体步骤：

1. 保存路径在截图那一刻按系统当前日期生成：`RootPath\yyyy-MM-dd\`，目录不存在就建；跨天后自动落到新日期目录，不缓存「今天」的字符串过夜使用——每次保存都现取系统日期。
2. 文件名生成算法固定为：先试 `集群名.png`，存在则依次试 `集群名-1.png`、`集群名-2.png`，取第一个不存在的名字写入。检查与写入之间留了并发空隙的顾虑在本工具单人单机场景下可忽略，但写入失败（文件被占用等）时顺延下一个序号重试一次，再失败才报错。
3. 格式只存 PNG（`ImageFormat.Png`），不提供 JPG 选项，理由同白皮书 6.3：文字和表格线条不能糊。
4. 写入失败兜底：根目录所在磁盘不可用、无写入权限时，把图暂存到程序所在目录并在面板显著提示暂存位置和失败原因，绝不静默丢图。
5. 保存成功后回填两件事：面板状态提示显示文件名，提供「打开今日文件夹」入口（直接用资源管理器打开当天日期目录）。

过关标准：同一集群连截 3 张，落盘为 `集群名.png`、`集群名-1.png`、`集群名-2.png` 且内容互不覆盖；把系统日期拨到次日再截，第一张重新从 `集群名.png` 开始；拔掉根目录所在的外置盘再截，图进暂存位置且有提示。

## 9. 阶段 6：凭据模块——10 个按钮，DPAPI 加密

目标：10 个凭据位从设置、存储到点击复制全链路走通，且任何环节看不到明文落盘。

具体步骤：

1. 加密调用 `ProtectedData.Protect`，范围固定 `DataProtectionScope.CurrentUser`，可选熵（附加口令式盐值）第一版不加——加了就得多管一个秘密，收益不大；明文先转 UTF-8 字节再加密，密文字节转 Base64 写进配置的对应凭据位。
2. 解密只发生在点击按钮的那一瞬间：`Unprotect` 后直接写剪贴板，明文不写日志、不进状态提示、不落任何临时文件。解密抛异常（配置从别的机器拷来、换了 Windows 账号等）时提示「该凭据需重新设置」，不崩溃。
3. 剪贴板写入用 `Clipboard.SetText`，失败（剪贴板被其他程序占用）时短间隔重试两三次，仍失败给提示。写入时记下所写内容的哈希，供下一步比对。
4. 自动清空：`AutoClearClipboard` 开启时，复制后起一个 30 秒计时；到点先比对当前剪贴板内容哈希与第 3 步记下的一致才清空，不一致说明使用者已复制了新东西，不动它。程序退出时计时器一并停掉，不留后台动作。
5. 面板凭据区固定渲染 10 个位：已设置的显示按钮名可点，未设置的置灰或隐藏（二选一，全程序统一）；按钮上永远只显示名字，不显示内容任何片段。

过关标准：填满 10 个凭据逐个点一遍，粘贴结果与原文一致；用记事本打开 `config.json` 全文搜索任一凭据原文，搜不到；把整个程序文件夹拷到另一台机器（或另一个 Windows 账号）打开，10 个凭据全部提示需重新设置、程序其他功能正常；开启自动清空后复制凭据、30 秒内改复制别的内容，到点后剪贴板里是新内容未被误清。

## 10. 阶段 7：设置窗口

目标：所有需要人维护的东西都收进一个设置窗口，改完保存立即生效，不重启程序。

设置窗口分四组，一组一块，不做多页签：

1. **集群：** 列表形式增删、改名、上下移排序；改名走阶段 1 的非法字符校验；删集群只删名单，明确提示不删历史截图。
2. **保存位置：** 显示当前根目录全路径，提供「更改」按钮弹文件夹选择框；同时显示配置文件的实际存放路径（含阶段 1 回退到 `%AppData%` 的情况），让使用者心里有数文件在哪。
3. **凭据（10 个）：** 每行一个凭据位——按钮名输入框 + 内容输入框 + 状态字样。内容框用密码掩码字符显示且不回显已存原文：已设置的只显示「已设置」，要改就清空重填覆盖，留空保存表示不改动原内容，另设「清除」动作把该位清空。**不提供查看原文的入口**，这是硬规矩，不因方便破例。
4. **选项：** 「复制后 30 秒自动清空剪贴板」开关、截图抓法偏好（自动 / 强制 PrintWindow / 强制 BitBlt），后者用于个别顽固软件单独处理。

保存动作统一走阶段 1 的配置层落盘，成功后刷新主面板的集群列与凭据区；校验不过关时停留在设置窗口并指出哪一项有问题，不许带着错误配置关窗。

过关标准：在设置里把集群从增删改排走一整轮、换一次根目录、改一个凭据、拨一次自动清空开关，主面板不重启全部即时生效；故意填一个带斜杠的集群名，被当场拦下。

## 11. 阶段 8：异常兜底、打包与实测验收

目标：把「演示能跑」变成「天天能用」，并产出可交付的单个 exe。

具体步骤：

1. 入口处挂全局异常处理（UI 线程与非 UI 线程各一处）：未预料异常只记到程序目录下的 `error.log`（只记异常类型、时间与操作环节，**绝不记凭据明文和截图内容**），界面给一句人话提示，程序能不退就不退。
2. 资源纪律：每次截图的位图、图形对象用完即释放；钩子、计时器在状态退出时成对卸载。连续截图 100 张内存无明显上涨，作为本阶段的硬指标实测。
3. 打包只做一件事：Visual Studio 出 Release 构建，产物就是单个 exe（外加首次运行自动生成的 `config.json`）。不打安装包、不做自动更新、不签名——未签名 exe 在部分机器上首次运行可能被 SmartScreen 拦一句，交付时口头说明点「仍要运行」即可，不为此引入证书成本。
4. 按下表逐项实测并留记录，全过才算第一版完成；任一项不过，回到对应阶段修，不在验收表上含糊放行。

## 12. 阶段 9：源码上 GitHub——建私有库

目标：源码进一个 GitHub 私有仓库，成为唯一的源码真源；任何人（包括以后的你）拿到仓库都能编译出同一个 exe。

### 12.1 建库

1. 仓库名建议 `inspection-widget`（最终名见第 14 节待确认），可见性选 **Private**。这个工具涉及巡检场景与集群命名习惯，源码和提交记录都不公开，没有商量余地。
2. 建库走 GitHub 网页或本机 `git` + 官方接口均可；建好后须把该仓库加入 Muse 官方 GitHub 连接器（账号 weizehan1）的可访问仓库选择里，之后柚子才能用连接器帮你读代码、看提交。注意区分：**连接器走的是快照式文件推送，只适合文本小批量同步，不用它推日常开发代码**；日常推送一律走本机 `git push`（见 12.3）。

### 12.2 入库前先立规矩：什么绝不能进仓库

`.gitignore` 第一次提交前就写好，至少排除：

- `config.json` 及其备份、损坏备份文件——里面有根目录路径和 DPAPI 密文，密文虽解不开，也没必要进仓库；
- `error.log`、截图产物（`*.png`）、日期文件夹；
- 编译产物：`bin/`、`obj/`、`.vs/`、`*.user` 等 Visual Studio 本地文件。

仓库里只放源码、清单文件、`.gitignore` 和 `README.md`。README 写清三件事：这是什么、怎么编译（VS 2022 + .NET Framework 4.8）、怎么运行（双击 exe、首次选目录）。第一次提交前用 `git status` 逐项核对暂存区，确认没有把本机在用的 `config.json` 带进去，这一步不能省。

### 12.3 推送与后续节奏

1. 开发机本地 `git init` 后关联远程仓库，首次推送把阶段 0 的骨架推上去，之后**每过一个阶段推一次**，提交信息按阶段写（如「阶段 4：截图引擎，PrintWindow + BitBlt 回退」），出问题能按阶段回退，不攒大包一次性提交。
2. 主分支只放能编译、能运行的代码；阶段 4 这种高风险段落可以先开分支试验，验收矩阵过了再合回主分支。
3. 每个对外可用的版本打一个标签（如 `v1.0`），并把该标签编译出的 exe 与标签对应关系记在 README 的版本记录里；分享给别人时（白皮书第 9 节：只发 exe 本体）发的就是某个标签对应的 exe。
4. 推送完成后用官方连接器读回仓库文件列表与最近提交各核对一次，确认远程与本地一致，再把仓库链接记入交付说明，才算本阶段过关。

过关标准：在另一台机器（或干净目录）克隆该私有仓库，按 README 操作能成功编译出可运行的 exe；仓库全文搜索不到任何凭据原文、`config.json` 和截图文件。
