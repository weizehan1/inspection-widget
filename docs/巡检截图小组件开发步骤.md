# 巡检截图小组件开发步骤（后端）

> 版本：v0.2 终审修订版 · 日期：2026-11-02。本版已并入远端审计修订（commit 3a1b47d）。
> 配套文档：《巡检截图小组件白皮书》v0.3。本文件只回答「后端按什么顺序、做成什么样、怎么验收」，不重新讨论需求；需求有冲突时以白皮书为准，本文件随白皮书同步修订。

## 1. 先说清两处前置约定

- **凭据按钮与折叠机制已对齐白皮书：** 凭据**最多 10 个、按实际配置数量显示**（配了几个就渲染几行，不用固定槽位、不留空槽），凭据区为**一行一个单列**布局，且凭据区支持点击分区标题收起/展开，折叠状态持久化保存（配置字段 `IsCredentialCollapsed`），用于小屏或集群较多时压低面板高度。本文件各阶段均按此定案执行。
- **前端视觉稿不在本文件范围内：** 界面视觉稿走 Figma 设计流程单独出图，你看图定版后，后端在阶段 2 和阶段 7 按定版稿对齐控件布局与配色；在此之前，后端先用朴素控件把状态机、布局伸缩和功能跑通，不等图、不阻塞。
- **当前状态：** 私有仓库已建立并已接入官方连接器，目前只有设计文档，没有工程、源码、测试或 exe。本文件的步骤与验收均是后续计划。

## 2. 总览：十个阶段，一关一关过

开发按依赖顺序拆成阶段 0 到阶段 8，外加阶段 9 的源码托管与发布收口。原则是：**每阶段有明确交付物和过关标准，上一阶段没过关，不进下一阶段**，避免最后所有问题挤在一起排查。

| 阶段 | 内容 | 交付物 | 粗估工时 |
| --- | --- | --- | ---: |
| 0 | 开发环境、工程骨架与本地 Git 初始化 | 能以管理员身份弹出的空面板 exe + `.gitignore` | 0.5 天 |
| 1 | 配置层 | `config.json` 读写与自愈模块 | 0.5 天 |
| 2 | 主窗口、底部锚定伸缩与面板状态机 | 右下角置顶小窗，折叠伸缩、最小化与还原正常 | 0.5–1 天 |
| 3 | 选窗与点击拦截 | 点中哪个顶层窗口识别无误，不误触目标窗口按钮 | 1 天 |
| 4 | 截图引擎 | 遮挡、缩放、多屏下都能抓到完整无黑边窗口图 | 1–2 天 |
| 5 | 保存与命名 | 按日期落盘、重名顺延、不覆盖、异常有暂存 | 0.5 天 |
| 6 | 凭据模块 | 凭据按钮（最多 10 个、按实际数量渲染）DPAPI 加密复制 + 30 秒安全清空 | 1 天 |
| 7 | 设置窗口 | 集群、根目录、凭据条目（可增减，最多 10 个）、选项可视化维护 | 1 天 |
| 8 | 异常兜底、打包与实测验收 | Release 单 exe + 11 项实测验收记录 | 1 天 |
| 9 | 源码上 GitHub 私有库与版本打标 | 私有仓库同步、连接器核验通过、源码可克隆编译 | 0.5 天 |

合计粗估 7–9 个工作日，为估算而非承诺；阶段 4 的坑最不可控，实际浮动主要出在这里。

## 3. 阶段 0：开发环境、工程骨架与本地 Git 初始化

目标：在一台 Windows 开发机上，把「双击 exe → 弹 UAC 确认 → 出现一个空面板」的链路先跑通，并把本地 Git 与 `.gitignore` 立好规矩。

具体步骤：

1. 开发机准备 Visual Studio 2022（版本选择遵守其许可）及「.NET 桌面开发」工作负载、.NET Framework 4.8 目标包；统一使用 MSBuild / VS Release 构建，不把系统旧版 `csc.exe` 当成等价构建环境。安装开发工具另行授权，不因本计划自动执行。
2. 新建 WinForms 项目，目标框架锁定 **.NET Framework 4.8**，全程统一，不中途换。目标机须具备 4.8+；Windows 10 早期版本和 Server 须另查。项目属性里关掉「首选 32 位」，平台选 Any CPU；全部句柄与指针用 `IntPtr` / `UIntPtr`，不能靠平台选项补救截断。发布清单记录实测的系统版本与位数。
3. 加入应用清单文件 `app.manifest`，写死两件事：
   - `requestedExecutionLevel` 设为 `requireAdministrator`，实现默认管理员启动；
   - 声明高分辨率 DPI 感知（`PerMonitorV2` 优先，并在 `Program.cs` 入口加 API 兜底声明），这是阶段 4 截图不发虚、不偏的前提，必须在第一天就声明好，后补容易漏测。
4. 引用的程序集全部限定为 .NET Framework 系统自带：`System.Windows.Forms`、`System.Drawing`、`System.Security`（DPAPI 用）、`System.Runtime.Serialization`（`DataContractJsonSerializer`）或 `System.Web.Extensions`（`JavaScriptSerializer`）。**不引入任何 NuGet 第三方包**，这是零依赖单文件的硬线。
5. 建好源码目录骨架，同时在根目录执行 `git init` 并写好 `.gitignore`（排除规则见阶段 9 的 12.2 节），保证从阶段 0 起每过一关就能干净提交一次：

```text
InspectionWidget/
├─ InspectionWidget.sln
├─ src/
│  ├─ InspectionWidget.csproj  工程与框架引用、嵌入 manifest
│  ├─ Program.cs          入口、DPI 兜底、单实例互斥锁、全局异常兜底挂载
│  ├─ MainForm.cs         主面板与状态机
│  ├─ SettingsForm.cs     设置窗口
│  ├─ Config/             配置模型与读写（阶段 1）
│  ├─ Capture/            选窗与截图（阶段 3、4）
│  ├─ Storage/            保存与命名（阶段 5）
│  ├─ Credentials/        DPAPI 与剪贴板（阶段 6）
│  └─ Native/             全部 Win32 P/Invoke 声明，集中一处
├─ app.manifest
├─ .gitignore
└─ README.md
```

过关标准：Release 编译出的单个 exe 拷到另一台没装开发环境的 Win10/11 机器上，双击弹管理员确认、确认后 1 秒内出现空面板，任务管理器里确认进程为高权限（管理员）且 DPI 感知列为「每个显示器 (v2)」；本地仓库已初始化，`.gitignore` 已落盘。

## 4. 阶段 1：配置层先行

目标：把 `config.json` 的模型、读写和自愈做完并单测过，后面所有模块只调这一层，不各自碰文件。

配置模型（字段与白皮书第 8 节一一对应）：

| 字段 | 内容 | 备注 |
| --- | --- | --- |
| `RootPath` | 截图保存根目录 | 首次为空，空即触发阶段 2 的选目录流程 |
| `Clusters` | 集群名列表（含有序） | 6–10 个量级，首次为空时初始化「集群1」「集群2」占位 |
| `Credentials` | 凭据条目列表，0–10 条，每条含按钮名（`Title`）+ DPAPI 密文（`EncryptedSecret`，Base64） | 上限 10 条不变，不用固定长度数组、不预置空位；条目数就是实际配置数，密文阶段 6 才填，本阶段先定结构 |
| `IsCredentialCollapsed` | 凭据区是否处于折叠收起状态 | 默认 `false`（展开），点击标题切换后持久化 |
| `AutoClearClipboard` | 复制后 30 秒自动清空开关 | 默认开启（`true`） |
| `CaptureMode` | 截图抓法偏好：自动 / 强制 PrintWindow / 强制 BitBlt | 默认自动 |
| `WindowLeft`、`WindowTop` | 面板上次位置 | 下次打开还原 |
| `LastCluster` | 上次选中的集群名 | 仅恢复视觉选择，打开时仍为待命，不自动挂钩 |

具体步骤：

1. **路径基准（防管理员目录漂移）：** 配置文件固定放 exe 同目录，文件名 `config.json`。注意：因程序以管理员身份启动，操作系统会把默认当前工作目录切到 `C:\Windows\System32`，代码中必须用 `AppDomain.CurrentDomain.BaseDirectory` 获取 exe 所在真实目录拼接路径，**严禁直接写相对路径 `"config.json"`**。启动时先探该目录可写性，不可写则回退到当前用户的本地应用数据目录（`%LocalAppData%\InspectionWidget\config.json`），并把实际路径记下来供设置界面展示。读取优先序：已有回退配置优先读取，否则先读取同目录配置，再判断能否写入；只读配置仍可加载，不得因可写性变化读回旧配置。运行中只认一个权威位置并显示实际路径；回退写入成功前保留原件，两处均不可写时提示「设置未保存」。以当前进程实际 Windows 身份读写，UAC 使用其他管理员账号启动时不视为原桌面账号（该情形的验收单独记录）。
2. **安全写入（原子替换）：** 采用「先写同目录 `.tmp` 临时文件、写完再覆盖替换正式文件」的方式：用 `File.Copy(tmp, target, overwrite: true)` 后删除 tmp（或用 `File.Replace`），避免写一半断电或崩溃把配置写坏。**注意不要直接对已存在文件调 `File.Move`，.NET Framework 下目标已存在时会抛 `IOException` 崩溃。** 读取配置前按规范化的权威配置路径取得跨会话互斥或进程生命周期文件锁，覆盖所有访问同一配置的实例，不能仅按用户名或会话隔离锁；锁占用或权限不足时提示并停止配置写入，不切换路径绕过。原子替换防止半写，互斥防止旧设置覆盖新设置，两者都需要。
3. **损坏自愈（分类处理）：** 文件缺失为正常首次初始化，不存在「备份缺失文件」；可选字段缺少时仅补默认值。语法或结构损坏先以不重名方式备份，再载默认值；备份失败不得覆盖原件。读取权限或 I/O 故障提示并保留文件，不按损坏配置重置。根目录确实遗失时明确提示恢复配置或重选，不能谎称已保存。
4. **单条密文隔离：** 单条凭据密文损坏或解不开时，只把那一条在内存状态中标记为「需重新设置」，不连累集群名单等其他配置整体重置。
5. **名称校验：** 集群名在设置保存与配置加载时统一校验：非法字符、控制字符、空名、. / ..、尾部点或空格、Windows 设备保留名（含带扩展名形式），按 Windows 大小写不敏感规则查重；最终保存时检查目录包含关系和带序号的路径长度。无效项提示修正，不默默替换后覆盖历史图。

过关标准：分别验证首次缺文件、缺少可选字段、乱码、字段类型错误、只读配置、回退目录重启、同目录恢复可写、备份失败、同会话及跨会话双实例（含共享配置的不同账号）。有效字段不丢失；有坏文件才备份；无法保存时明确提示且原件不变；已持久化的根目录重启不再主动询问。

## 5. 阶段 2：主窗口、底部锚定伸缩与面板状态机

目标：面板的「形」先立住——位置、置顶、折叠伸缩、最小化、状态切换都对，按钮先摆占位，点击业务逻辑留给后续阶段接。

具体步骤：

1. 窗体设为无边框或细边框、`TopMost` 置顶，首次启动定位到主显示器工作区（`WorkingArea`）右下角、任务栏上方；之后按配置里记的位置还原，位置越界（比如拔掉副屏）时自动收回主屏可见范围。
2. 最小化只做一件事：缩到任务栏。`ShowInTaskbar` 保持开启，不建托盘图标、不写托盘菜单；点任务栏图标按系统默认行为还原，不额外写代码干预。
3. 面板内容自上而下排：
   - 顶部行：程序名、当天日期、设置、最小化按钮；不放根目录；
   - 中部：集群按钮列（一列竖排，6–10 个）；
   - 分隔线 + **可折叠凭据区**：分区标题栏可点击，切换收起/展开下方凭据按钮。凭据按钮**按凭据条目的实际数量渲染**（有几个显示几个，**一行一个单列**，只显示按钮名），不渲染未配置的空槽；条目为 0 时凭据区只显示一行提示「未设置凭据，去设置添加」，不显示任何按钮行。状态实时写入配置的 `IsCredentialCollapsed`。**高度伸缩规则：** 凭据条目数量变化时，面板高度随实际行数增减；当展开/收起凭据区、凭据条目增减或增删集群导致窗体高度变化时，必须以窗体底边（`Bottom`）为锚点向上伸缩——即保持 `Bottom` 不变反算 `Top`，并钳制 `Top` 不超出当前屏幕 `WorkingArea` 上沿，防止面板向下伸长捅进任务栏底下；
   - 底部两行：反馈一行、保存根目录常驻一行；点击根目录行打开今日文件夹。反馈消失不隐藏根目录行。
4. 面板内部定三态状态机，全程序只认这三态，不许各处自己记标志位：
   - **待命：** 默认态，集群按钮可点，凭据按钮可点；
   - **待截图：** 点了某个集群后进入，高亮该集群并提示「请点击要截图的窗口」，按 Esc、点右键或再点一次该集群回到待命；若直接点另一个集群，则将选中目标切换为新集群并保持待截图状态；
   - **处理中：** 选窗完成后卸载输入钩子，固定本次集群、根目录、采集日期和请求编号，再异步截图与保存；禁用新截图及凭据操作，防止重复请求或误操作。失败且尚未落盘时保留当前图供重试，离开前显式确认放弃；旧请求的迟到结果不得改变当前状态。
   - **提示层（独立于状态机）：** 保存或复制成功后约 2 秒显示结果（如文件名、「已复制」），提示消失不改业务状态。
5. 首次启动且 `RootPath` 为空时，先弹文件夹选择框；用户取消则明确提示「未选目录，截图暂不可用」并在面板上禁用截图、引导先选目录，不许默默用某个默认路径把图存到不明处。一旦选定成功，后续启动直接沿用，不再弹窗询问。

过关标准：面板打开后停在右下角且不被其他窗口盖住；点击凭据区标题能顺滑向上展开、向下收起且底边不越过任务栏，重开程序折叠状态保持不变；凭据只配 5 条时面板只显示 5 行、凭据为 0 条时只显示「未设置凭据，去设置添加」一行提示，两种情况下高度都按底边锚定规则正确伸缩；最小化、任务栏还原、拖动位置记忆、三态切换全部符合白皮书第 4 节描述。

## 6. 阶段 3：选窗——第二下点到的是哪个窗口

目标：在待截图状态下，使用者点屏幕任意目标窗口，程序能准确说出「他点的是哪个顶层窗口」，并且这一下点击绝不误触发目标程序里的业务按钮。

具体步骤：

1. **按需挂钩与防回收：** 进入待截图状态时，在独立且有消息循环的线程安装低级鼠标钩子（`WH_MOUSE_LL`）和键盘钩子（`WH_KEYBOARD_LL`，专门监听全局 Esc 键取消，解决焦点不在小组件上时普通 `KeyDown` 收不到 Esc 的问题）；退出待截图状态（截完、取消、超时）立刻卸载钩子，平时绝不常驻。注意：钩子回调委托必须用静态或类成员变量强引用持有，防止被 .NET 垃圾回收器（GC）回收导致进程闪退；钩子只做坐标、顶层句柄及排除判定，立即返回。标题读取、截图、磁盘操作不在钩子或 UI 线程做，禁止把重活派回 UI 线程；重活在工作线程执行，UI 只收结果与进度（`BeginInvoke` 只回 UI 更新状态与提示），防止超时被系统摘钩。
2. **区分点自己还是点外部（关键顺序）：**
   - 当钩子收到左键按下（`WM_LBUTTONDOWN`）时，**先判断鼠标坐标是否落在小组件自身窗口矩形（`MainForm.Bounds`）内**：
   - 若落在小组件自身内：钩子直接**放行**该点击（`CallNextHookEx`），让小组件自己的界面正常响应——比如使用者点同一个集群取消、点另一个集群切换目标、或点了小组件空白处忽略；
   - 若落在小组件外部：钩子**吞掉**这次 `WM_LBUTTONDOWN`，并设标志位同步吞掉紧接着的那一次 `WM_LBUTTONUP`（按下与抬起必须成对吞掉，只吞 Down 不吞 Up，目标窗口收到孤立的 `MouseUp` 仍会触发网页或客户端按钮），随后卸载钩子并通知主线程按该坐标选窗。
   - 收到右键按下（`WM_RBUTTONDOWN`）或全局 Esc：吃掉消息并异步通知 UI 线程取消待截图状态。
   - 派发工作时携带请求编号、句柄与进程身份，执行前复核窗口仍存在且没有最小化或被替换。
3. **窗口反查与排除名单：** 主线程拿到坐标后，用 `WindowFromPoint` 取最内层子窗口句柄，再用 `GetAncestor(hwnd, GA_ROOT)` 追溯到顶层窗口；若追溯结果是桌面（`Progman` / `WorkerW`）、任务栏（`Shell_TrayWnd` / `Shell_SecondaryTrayWnd`）或组件自身，本次点击忽略并重新挂回钩子保持待截图状态，不报错、不退出。同时取出顶层窗口标题，仅用于状态提示里让使用者确认选对了对象，不参与文件命名。
4. **最小化窗口处理：** 追溯到的窗口若处于最小化状态（`IsIconic`），不截图，提示「该窗口已最小化，请先打开」，并回到待命状态。
5. **超时兜底：** 待截图状态加一个 30 秒无操作自动超时，到点自动卸载钩子回到待命状态，防止使用者点完忘了这回事导致下次点击被吞。
6. **收尾与释放保证：** 若按下后取消或超时，停止接受新选择，但仍配对处理该次抬起后退出；不补发点击。安装失败提示并回待命。退出、异常和取消都保证钩子释放。

过关标准：拿记事本、浏览器、资源管理器、一个巡检类客户端各点一轮，提示出的窗口标题与实际点中的程序一致；待截图时再点组件上的集群按钮能正常取消或切换集群；点桌面、点任务栏都不误截；直接点在目标窗口的「关闭」按钮上，截图选窗成功且目标窗口没被关掉；焦点在其他窗口时按 Esc 也能取消待截图。

## 7. 阶段 4：截图引擎——整个开发最难的一段

目标：给定一个顶层窗口句柄，稳定产出一张完整、不黑、不虚、不带多余阴影边的内存位图。这一阶段按白皮书 6.2 的组合策略做，不许只实现一种抓法就往下走。

具体步骤：

1. **同时取两个矩形：**
   - 用 `GetWindowRect` 取窗口包含透明阴影的完整矩形 `winRect`；
   - 用桌面窗口管理器接口 `DwmGetWindowAttribute` 取窗口的实际可视边界（`DWMWA_EXTENDED_FRAME_BOUNDS`）`dwmRect`；
   - 多显示器下坐标可为负数，全程用真实物理屏幕坐标，不做从零假设；
   - DWM 查询失败时使用经校验的窗口矩形并注明可能含透明边，不对空、反向或异常大矩形分配位图。
2. **首选 PrintWindow + 内存裁阴影边：**
   - 先按 `winRect` 的宽高创建内存位图，调用 `PrintWindow(hwnd, hdc, PW_RENDERFULLCONTENT /* 0x00000002 */)` 让窗口把完整画面（含硬件加速合成层）重绘出来，被遮挡的部分也能抓全。**严禁直接按 `dwmRect` 尺寸建位图调 PrintWindow**——PrintWindow 永远从含阴影的完整窗口左上角（即 `GetWindowRect` 原点）开始绘制，直接按 DWM 无阴影尺寸建位图会导致左边和上边依然带 7 像素透明黑边、右边和下边被硬生生截断 7 像素；
   - 重绘完成后，按 `dwmRect` 相对于 `winRect` 的四边偏移量，在内存中把四周约 7 像素的透明阴影边裁掉，只保留 `dwmRect` 大小的干净窗口图。
   - **线程与所有权：** `PrintWindow` 是同步阻塞调用，不能在 UI 或钩子线程调用。超时使请求失效，可用另一张独立位图回退 BitBlt；原调用未返回前不启动新的 PrintWindow，不释放或复用其 DC / 位图，返回后丢弃迟到结果并释放。`PW_RENDERFULLCONTENT` 的目标兼容性单独实测记录。
3. **黑图检测：** 对裁好后的位图做网格采样检测——均匀取约 200 个采样像素点，全黑 `RGB(0,0,0)` 或全透明占比超过 98% 即判为失败。只判采样点、不逐像素扫描，保证几毫秒内出结果。
4. **回退 BitBlt（含小组件防自遮挡）：**
   - 当 PrintWindow 返回失败或被判黑图，且设置里的抓法不是「强制 PrintWindow」时自动回退：先把目标窗口置前（`SetForegroundWindow` + `BringWindowToTop`），必须检查置前结果，禁止靠 `BringWindowToTop` 假定必然成功，不强行模拟点击或绕过前台限制；置前被拒时提示用户处理；
   - **防自遮挡：** 检查目标窗口 `dwmRect` 是否与置顶的小组件自身矩形相交，若相交则先把小组件临时设为全透明（`Opacity = 0`），等待约 60 毫秒让系统桌面合成器刷新画面；
   - 直接按 `dwmRect` 的屏幕坐标从屏幕设备上下文执行 BitBlt（或 `CopyFromScreen`）拷贝像素，抓完立刻恢复小组件显示（`Opacity = 1`）。
5. **DPI 校准：** 进程已在阶段 0 声明 PerMonitorV2 感知；在 125%、150% 缩放屏幕及跨不同缩放比的多屏环境下，复核 `dwmRect` 获取的是否为真实物理像素尺寸，确保截出的图 1:1 清晰锐利，不发虚、不缺失右下角。截图前后窗口移动或尺寸变化则使本次结果失效，提示重试。强制 PrintWindow / 强制 BitBlt 不切换方法。
6. **特殊受保护窗口的预期管理：** 若回退 BitBlt 后采样检测依然是纯黑图（如受版权保护的 DRM 视频或系统安全桌面，见白皮书第 10 节），给明确提示「该窗口可能受系统保护，截不到画面」，释放位图、不落盘黑图文件、不假装成功。

过关标准：验收矩阵逐格过——目标窗口分别处于「被其他窗口遮一半、完全未遮挡、位于右下角与小组件重叠、在副屏（负坐标）上、所在屏缩放 150%、最大化、普通窗口化」七种情形下，产出图均完整、无阴影黑边、无小组件残影且文字清晰；测黑图路径时程序给提示且不落盘黑图。另补测六项：跨屏不同缩放、纯色合法窗口、目标移动、置前被拒、窗口部分出屏、PrintWindow 阻塞。

## 8. 阶段 5：保存与命名

目标：把阶段 4 的内存位图按白皮书第 7 节规则稳妥落盘，一张都不许丢、一张都不许覆盖错。

具体步骤：

1. 每次请求在采集开始时读取一次系统日期，固定集群名、根目录与日期，保存为 `RootPath\yyyy-MM-dd\`，目录不存在就建；落盘重试沿用本次日期；下一次采集重新读取。跨午夜时同一张图不因保存耗时改归属，不改生产机系统日期做验收。
2. 文件名生成算法固定为：先试 `集群名.png`，存在则依次试 `集群名-1.png`、`集群名-2.png`。使用 `FileMode.CreateNew` 原子占用第一个可用名称；只对确定的重名冲突顺延，其他 I/O 故障直接进入兜底。对并发重名设有界重试并可取消，不可无限循环。
3. 格式只存 PNG（`ImageFormat.Png`），不提供 JPG 选项，理由同白皮书 6.3：文字和表格线条不能糊。
4. **磁盘异常暂存兜底：** 当 `RootPath` 所在磁盘不可用（如移动硬盘拔出、网络盘断开）或无写入权限时，优先暂存到 exe 所在目录下的 `FallbackScreenshots\yyyy-MM-dd\` 中（路径同样用 `AppDomain.CurrentDomain.BaseDirectory` 拼接），同目录也不可写则尝试 `%LocalAppData%\InspectionWidget\FallbackScreenshots\yyyy-MM-dd\`；沿用不覆盖规则并显示实际路径。两处均失败时保留当前内存图供重试，提示「尚未保存」，绝不静默丢图。
5. 保存成功后回填两件事：面板状态条显示对勾与文件名（持续约 2 秒），底部常驻根目录行点击打开今日文件夹（用资源管理器打开当天日期目录并选中最新截图）。目标尚不存在时只提示「今天尚无截图」，不为打开目录制造空日期文件夹。

过关标准：同一集群连截 3 张，落盘为 `集群名.png`、`集群名-1.png`、`集群名-2.png` 且内容互不覆盖；用可注入时钟或隔离测试机验证跨天第一张重置与跨午夜归属；模拟同名竞争、写入中断、根目录离线和两级暂存均不可写。

## 9. 阶段 6：凭据模块——按实际数量（最多 10 个），DPAPI 加密

目标：凭据条目（0–10 条）从设置、加密存储到点击复制、自动清空全链路走通，任何环节看不到明文落盘。

具体步骤：

1. 加密调用 `ProtectedData.Protect`，范围固定 `DataProtectionScope.CurrentUser`，第一版不加额外熵（盐值）；明文先按 UTF-8 转字节再加密，密文字节转 Base64 写进 `config.json` 的对应凭据条目。
2. 解密只发生在点击按钮的那一瞬间：`Unprotect` 后直接写剪贴板，明文不写日志、不进状态提示、不落任何临时文件。解密抛 `CryptographicException`（如配置从别的机器拷来、换了 Windows 账号）时，界面提示「该凭据需重新设置」，不崩溃。
3. 在 STA 线程写入 Unicode 文本及 Windows 的 `CanIncludeInClipboardHistory` / `CanUploadToCloudClipboard` 禁用标志。使用同一次 `OpenClipboard` 锁保护写入、令牌与 `GetClipboardSequenceNumber` 记录，不能 `Clipboard.SetText` 释放锁后才读取序列号；异常只有限重试，失败不提示「已复制」。写入成功时另计算并记下所写文本的 SHA256 哈希值作辅助（不存明文副本）。
4. **30 秒自动清空与退出兜底：**
   - `AutoClearClipboard` 开启时，每次点击复制后启动（或重置）一个 30 秒计时器；
   - 到点在同一次 `OpenClipboard` 锁内核对序列号和本次令牌，仍是本次写入且未变更才 `EmptyClipboard`，`finally` 释放锁。无法加锁或无法可靠核对时跳过并提示，不冒险清空；同文字的新复制也不得清除；
   - **程序退出兜底：** 如果在 30 秒倒计时还没结束时使用者关闭了程序，在 `FormClosing` 事件中立即执行一次上述同锁核对，若剪贴板里仍是刚复制的凭据，当场清空后再退出，防止密码残留在系统剪贴板。
5. **面板按实际条目数渲染、无空槽：** 主面板凭据区按 `Credentials` 条目的实际数量渲染按钮行（一行一个单列），有几条显示几行，全部可点；不渲染未配置的空槽位、不用置灰的占位按钮撑高度；条目为 0 时只显示一行提示「未设置凭据，去设置添加」。按钮上永远只显示名称，绝不显示密码内容。

过关标准：只配 5 个凭据时面板只显示 5 行、高度正确，无空槽、无置灰占位；上限压测：填满 10 个凭据逐个点一遍，粘贴结果与原文一致；用记事本打开 `config.json` 全文搜索任一凭据原文，搜不到；把整个程序文件夹拷到另一台机器（或另一个 Windows 账号）打开，已配置的凭据全部提示需重新设置、程序其他功能正常；开启自动清空后测试：① 30 秒不操作自动清空；② 30 秒内改复制别的文字不被误清；③ 复制后 5 秒内直接关掉程序，剪贴板被立即清空；④ 新内容与旧文字相同、连续复制凭据、关闭开关、剪贴板被占用四项补测。

## 10. 阶段 7：设置窗口

目标：所有需要人维护的东西都收进一个设置窗口，改完保存立即生效，不重启程序。

设置窗口分四组，一组一块，不做多页签：

1. **集群：** 列表形式增删、改名、上下移排序；新增与改名走阶段 1 的非法字符及重名校验；删集群只删名单，界面注明不删已保存的历史截图。
2. **保存位置：** 显示当前根目录全路径，提供「更改」按钮弹文件夹选择框；同时只读显示 `config.json` 的实际存放路径（含阶段 1 回退到 `%LocalAppData%` 的情况），让使用者心里有数文件在哪。
3. **凭据（可增减的条目列表，最多 10 条）：** 操作方式与上面的集群管理一致——条目列表 +「添加」「删除」维护条目，每条可改名、改内容，也可单独「清除」其内容；不再是固定 10 行表格，没有条目时列表为空、点「添加」新增第一条，已达 10 条时「添加」禁用并提示已达上限。每条一行：按钮名输入框 + 内容输入框 + 状态字样 +「清除」按钮。内容框用密码掩码字符（●）显示且绝不回显已存原文：已设置的只显示状态「已设置（留空不修改，输入新内容则覆盖）」，点「清除」只清该条内容、保留条目，点「删除」才连条目一并移除。**不提供查看原文的入口**，这是硬规矩，不因方便破例。
4. **选项：** 「复制后 30 秒自动清空剪贴板」开关、截图抓法偏好（自动 / 强制 PrintWindow / 强制 BitBlt），后者用于个别顽固软件单独处理。

保存动作统一走阶段 1 的配置层落盘，成功后立即刷新主面板的集群列、凭据区及窗口高度（按阶段 2 的底边锚定规则自适应）；校验不过关时停留在设置窗口并指出哪一项有问题，不许带着错误配置关窗。

过关标准：在设置里把集群从增删改排走一整轮、换一次根目录、给凭据列表添加一条、删除一条、改一条的名称与内容、清除一条的内容、拨一次自动清空开关，主面板不重启全部即时生效（凭据行数随条目数同步增减）；故意填一个带斜杠 `\` 或 `:` 的集群名，被当场拦下。

## 12. 阶段 9：源码上 GitHub 私有库与版本打标

目标：源码进一个 GitHub 私有仓库，成为唯一的源码真源；任何人（包括以后的你）拿到仓库都能直接编译出同一个 exe。

### 12.1 建库与连接器授权（现状）

1. 仓库名已定为 `inspection-widget`，可见性为 **Private**，**仓库已建好并已接入 Muse 官方 GitHub 连接器**（账号 weizehan1），柚子已可用连接器读代码、看提交。这个工具涉及巡检场景与集群命名习惯，源码和提交记录都不公开，没有商量余地。

### 12.2 入库红线：什么绝不能进仓库

阶段 0 建好的 `.gitignore` 在第一次向远程推送前再核对一遍，必须排除：

- `config.json` 及其备份、损坏备份文件（`config.*.json`）——里面有根目录路径、集群名和 DPAPI 密文，密文虽解不开，也没必要进仓库；
- `error.log`、截图产物（`*.png`）、日期文件夹、暂存文件夹（`FallbackScreenshots/`）；
- 编译产物与本地缓存：`bin/`、`obj/`、`.vs/`、`*.user`、`*.suo` 等 Visual Studio 本地文件。

仓库里只放源码、项目工程文件（`.sln` / `.csproj`）、`app.manifest`、`.gitignore` 和 `README.md`。README 写清三件事：这是什么、怎么编译（VS 2022 + .NET Framework 4.8 Release）、怎么运行（双击 exe、首次选目录）。推送前用 `git status` 逐项核对，确认没有把本机在用的 `config.json` 带进去。`.gitignore` 不能移除已被跟踪的敏感文件，发现后须单独报告与处置，不能把新增忽略规则当成历史清理。第一次提交前用 `git status` 逐项核对暂存区。文档中出现 `config.json` 文件名或示例不算泄露。

### 12.3 推送与版本标签节奏

1. 开发过程中每过一个阶段（阶段 0 ～ 阶段 8）在本地提交一次（若已建好远程库则同步 `git push`），提交信息按阶段写（如 `feat(stage-4): 截图引擎，PrintWindow + DWM裁边 + BitBlt回退`），出问题能按阶段精准回退，不攒大包一次性提交。
2. 主分支（`main`）只放能编译、能通过当前阶段验收的代码；阶段 4 这种高风险段落可先开分支试验，验收矩阵过了再合回主分支。
3. 阶段 8 全部验收通过后，在本阶段给代码打上正式标签（如 `v1.0.0`），并把该标签编译出的 exe 文件大小、SHA256 校验值与标签对应关系记在 README 的版本记录里；分享给别人时（白皮书第 9 节：只发 exe 本体）发的就是该标签对应的单个 exe。开发后记录工具版本、构建命令和产物哈希，不把「可构建」等同于字节完全一致。
4. 推送完成后用官方连接器读回仓库文件列表与最近提交各核对一次，确认远程与本地一致，再把仓库链接记入交付说明，才算本阶段过关。

过关标准：在另一台机器（或干净空目录）克隆该私有仓库，按 README 操作能一键编译出可运行的单个 exe；仓库历史记录与全文件搜索不到任何凭据原文、`config.json` 和截图文件。
