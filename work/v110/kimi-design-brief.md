# PD：Kimi 3.1 Pro 前端设计任务

先读 `docs/superpowers/specs/2026-11-14-next-version-design.md` 的产品基线、UI 重做目标和 A–E 功能。这份文件是需求依据。只读研究 MainForm、SettingsForm、PanelLayout 和 README，现有 WinForms/.NET Framework 4.8、无新增运行依赖、右下角常驻/托盘/滚动/截图时隐藏是必须保留的约束。

用户直接反馈：“前端界面一方面是不合理，第二方面是十分简陋，一点也不美观”。请重新组织交互结构并建立统一视觉，不要只换颜色或把现有控件堆得更大。布局宽度可改变，不受现有 230 逻辑像素限制。

交付路径，只可写这些路径：
- `docs/design/v110/preview.html`：完整自包含、无需网络的交互预览，提供 A/B 两个真正不同结构的方案，能切换主面板/设置页，模拟正常、等待选窗、保存中、失败、全勾状态。真实内网地址不出现，示例使用 example.invalid；无真实凭据或截图。
- `docs/design/v110/recommendation.md`：当前问题（区分源码推断和真实实测）、两方案区别、推荐及原因、默认尺寸、长名单/大字体/多屏适配和 WinForms 可实现性。
- `docs/design/v110/design-contract.md`：两方案的视觉规范、控件业务状态映射、待用户选择的唯一结构差异。DESIGN.md 等到用户选择后再固化，不提前宣称某方案获批。

主面板需要一眼区分：日期、链接、截图设备及已点过对勾/计数、凭据复制、底部打开巡检文件夹。对勾=点击被接受后已点过；不是截图成功。重复点击可再次截图不取消对勾；截图中/失败等状态用文字与形状辅助，不能只靠颜色。
设置页覆盖设备、凭据、快捷链接、存储、配置备份与应用/保存/取消；关键设置可滚动。完成询问在截图/保存结束后出现，不抢选窗焦点。

请运用你的前端设计能力（可参考适用 skill，但不更换指定模型、不另派 agent）；用精确字体层级、留白、边界、按钮状态和克制的视觉呈现高质量桌面工具。避免大屏仪表盘式空白、无关数据卡、花哨装饰和只做静态假按钮。

读完即执行，无需先问是否继续。遇到细节在报告标为建议；交付两方案，由用户选定后进入正式 WinForms 实现。完成后报告准确文件路径，不宣称 Windows 实机已验收。
